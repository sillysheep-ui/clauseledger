# 重排该放在哪一层：一次把尺子对齐的实验

## 一句话

重排不提升"文件排第 1"，但提升"模型看到的内容"和"答案里的数字"——
**判断重排有没有用，必须在生成层看，不是在检索层看**。

## 为什么要重排，以及它原来为什么没用

我们之前测过重排（`BAAI/bge-reranker-base`，cross-encoder）：

- 同一分母（n=134，BM25 top-50 池）下，P@1 **42.5% → 48.5%**（条款）、**50.7%**（条款+父条首句）。
- 但接进流水线后，端到端反而**变差**：作答 95%→77%，精度 71%→70%。

原因是两把尺子：重排改了顺序，`decide()` 判断"敢不敢答"时读的却是
**重排后第一名那条的 BM25 分**。语义对、BM25 分低的条款被顶上来，立刻被
判成"不敢答"。

## 改法：把重排分做成判据的一项

`app/retrieval/rerank.py` 在排序前把分数写进 `h._rr`；
`app/retrieval/confidence.py` 新增 `rr` 项（sigmoid 后的重排分）：

```
score = 0.45·rr + 0.20·lex + 0.10·margin + 0.25·cos     # rr 模式
score = 0.40·lex + 0.25·margin + 0.35·cos               # 无重排
```

阈值分离：`CLAUSELEDGER_CONF_T_RR`（默认 0.50）与 `CLAUSELEDGER_CONF_T`（0.38），
因为两套分数的分布不同。

## 三层实测（同一语料、同一 dev 题）

| 层 | 指标 | 重排关 | 重排开 |
|---|---|---|---|
| 上下文 | 给模型的条款覆盖官方答案句 | 51.4% | **62.9%** |
| 上下文 | 其中"文件对、但条款没进上下文" | 8 题 | **4 题** |
| 生成 | 官方「数字+单位」事实覆盖 | 24.4%（10/41） | **36.6%（15/41）** |
| 生成 | 句子核验通过率 | 73.5% | 71.3% |
| 检索 | 文件 R@10 | 84% | 87% |
| 检索 | P@1\|R@10（文件级） | 86% | 73% |
| 决策 | 作答率 / 作答精度 | 95% / 71% | 87% / 67% |

**读法**：重排优化的是"条款级相关性"，所以它在
- 条款级指标（上下文覆盖、生成事实覆盖）上是**正收益（+11.5pp / +12.2pp）**；
- 文件级指标（P@1）上是**负收益**——因为它会让另一份文件里"更像答案"的条款
  排到前面。

我们真正交付的是"带引用的答案"，所以按生成层定去留：**默认开启**。

## 代价

- 单查询约 +1 秒（cross-encoder，MPS），BM25 是 2 毫秒。
- 首次加载模型约 400 MB 内存。
- 缺模型/离线时自动降级回 BM25，并在 `Answer.searched["rerank"]` 里记 `"off"`。

## 怎么验证

```bash
# 三层一起看
.venv/bin/python -m tools.eval_recall          # 召回层
.venv/bin/python -m tools.eval_context         # 上下文层
.venv/bin/python -m tools.eval_generate --k 5 --write   # 生成层
CLAUSELEDGER_RERANK=0 .venv/bin/python -m tools.eval_generate --k 5 --write  # 对照
```

## 结论与边界

- 这不是"重排没用"，是"重排的收益落在生成层，不落在检索层"。
- 文件级 P@1 的下降是真实代价，别拿它当卖点。
- 如果以后换成"只给链接列表"的产品形态，重排就该关掉。

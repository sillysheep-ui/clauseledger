# 混合召回：BM25 + 稠密 + RRF

> 一句话：**默认已开**（`CLAUSELEDGER_RECALL` 不设就是 `hybrid`）。在"官方措辞"问题上它不涨分（−1pp，噪声内），
> 但在"口语提问"上 +2/−0（41%→50%，n=22，不显著）。这一页记录"加了什么、两种口径各测出什么、为什么这样取舍"。

## 1. 为什么加

用户要求"加上 RRF"。此前 `tools/experiments/recall_compare.py` 的受控实验里，四路召回是：

| 方法 | hit@1 | 与 BM25 的配对检验 |
|---|---|---|
| A BM25 | 55.4% | — |
| B BM25 + 字二元组 | 60.9% | 9 好 4 坏，p=0.267 |
| C 稠密（bge-small-zh） | 56.5% | 11 好 10 坏，p=1.000 |
| D A+C 的 RRF | 60.9% | 8 好 3 坏，p=0.227 |

四路都没过"≥6:0"的显著门槛，当时的结论是**一个都不上线**。所以这次不是"发现有收益"，而是**把开关做出来**，让"换召回方式"这件事可复现、可审计。

## 2. 加了什么

**`app/retrieval/dense.py`（新）**

| 函数 | 作用 |
|---|---|
| `available()` | 依赖/模型在不在；不在就降级 |
| `matrix(children)` | 6,064 个子块的向量矩阵，缓存到 `data/index/dense_children.npz`，缓存键是子块内容的 sha |
| `rank(query, children, k)` | 余弦 top-k，返回 `[(子块下标, 相似度)]` |
| `rrf(a, b, k=60)` | `Σ 1/(k + rank_i(d))`，只用名次不用分数 |

**`app/retrieval/search.py`（改）**

- `RECALL = env CLAUSELEDGER_RECALL`，取值 `bm25`（默认）/ `dense` / `hybrid`。
- `_candidates()` 统一出候选：BM25 一路；hybrid 时两路取回、`rrf` 融合、按 pid 回填。
- **分数口径**：RRF 只给名次，分数按"当次最高 BM25 分 × (rrf / 最高 rrf)"线性映射。这样 `min_score=3.0`、`min_score_strong=6.0` 这两个阈值的语义不变——换召回方式不该偷偷改判据。
- `Answer.searched["recall"]` 记实际模式；**未覆盖/不在域内的提前返回写 `none`**，不许把上一次的 `bm25` 留在痕迹里。
- `_load()` 加缓存（键是索引文件 mtime）。不缓存时每次查询重读 6 千条款要 ~1 秒，会让"混合召回慢"的结论失真。

**`tests/test_hybrid.py`（6 条）**：RRF 只认名次、并集、可复现；模式默认 bm25；模型缺失降级；`searched.recall` 如实记录（含 `none`）。全套 **205 通过**。

## 3. 实测（dev 官方题 n=92，完整流水线：闸门 + 年份 + 类型加分 + 合并）

| 模式 | hit@1 (95%CI) | hit@3 | MRR | 应答率 | 已答中 hit@1 |
|---|---|---|---|---|---|
| bm25（默认） | **61%（51–70）** | **79%** | **0.74** | 88% | **69%** |
| hybrid, k=10 | 59%（48–68） | 79% | 0.72 | 88% | 67% |
| hybrid, k=20 | 60%（50–69） | 77% | 0.73 | 88% | 68% |
| hybrid, k=60 | 60%（50–69） | 76% | 0.72 | 88% | 68% |

含门控负样本（113 条）整体耗时：bm25 **4.1 秒**、hybrid **42.0 秒**（≈360ms/题 vs 36ms/题）。

单查询热态延迟：bm25 **2–20ms**；hybrid **100–150ms**（其中稠密编码 30–100ms）。首次调用要多等模型加载（约 20 秒）。

## 4. 为什么"受控实验 +3pp，线上却 −1pp"

受控实验（`recall_compare.py`）只比"检索排序"，流水线里还有四层会重排：

1. 覆盖率闸（0.30 地板 / 0.25 候选）——先把一批候选砍掉；
2. 年份过滤/分层——问 2019 年时跨年候选直接出局；
3. 标题加权（0.6/词）与效力 ×1.08/×1.2——这两项在 BM25 分差之上，能翻盘；
4. 回答类型加分（0.9/个数字）——专治"同文件挑错条款"。

**结论：在只比排序时 RRF 有微弱优势；进了流水线，被后面几层吃掉了，甚至因为分数被映射压平而略差。**

另一个结构原因：`tools/experiments/rerank_pool.py` 量过，**稠密池与 BM25 池的并集就是 BM25**——两路看到的是同一批文档。RRF 能修的是"名次抖动"，修不了"证据缺失"。

## 5. 怎么打开

```bash
export HF_HOME="$PWD/.hf-cache"        # 沙箱里 ~/.cache 不可写
export CLAUSELEDGER_RECALL=hybrid
export CLAUSELEDGER_RRF_K=60           # 可选，默认 60
python -m tools.ask "失业保险金怎么领"
```

`tools/ask.py` 会打印 `searched.recall`，模型缺失时如实显示 `bm25`（降级），不会假装用了混合。

## 6.5 口语提问：这才是 RRF 该起作用的场景

上面 92 条 dev 题是**官方问答**——问题本身就是政策标题的改写（"申报下一年度工伤预防项目需要提交哪些材料" vs 标题"关于印发《上海市工伤预防费使用管理试行办法》的通知"），词面高度重合，所以 BM25 已经够用，稠密没有增量。

真实用户不会这么问。于是新建 `eval/questions_paraphrase.json`：把 22 条 dev 题改写成口语（不改金标），例如：

| 官方问法 | 口语问法 |
|---|---|
| 灵活就业人员可在哪些渠道办理就业和参保登记？ | 自己交社保的灵活就业人员，去哪儿办就业登记？ |
| 职业年金应如何转移接续？ | 换工作了，职业年金怎么转过去？ |
| 本市工伤人员外省市就医食宿费标准是多少？ | 工伤的人去外地看病，住宿吃饭的钱谁出、多少？ |

结果（同 22 条、同金标、只换召回）：

| 模式 | hit@1 (95%CI) | 变动 |
|---|---|---|
| bm25 | **9/22 = 41%（23–61%）** | — |
| hybrid | **11/22 = 50%（31–69%）** | 改好 2、改坏 0 |

改好的两条：
- `PARA-009` 灵活就业登记：BM25 给 `沪人社就发〔2015〕38号`（旧文），hybrid 给 `沪人社规〔2023〕25号`（正确）；
- `PARA-011` 职业年金转移：BM25 给 `沪人社规〔2019〕26号`（错），hybrid 给 `〔2019〕29号`（正确）。

**方向上和理论一致**：口语和条文用词不重合时，稠密的语义匹配补上了词面缺口。但 n=22、2:0，统计上不显著——只能说"不亏，且给了正确方向的证据"。

顺带暴露另一个缺口：这 22 条里有 **6 条被拒答**（27%），因为口语里没有域词（"为啥要让建筑工地都上工伤保险"里没有"工伤"以外的政策词）。这是**覆盖率/领域闸**的问题，不是召回的问题，记在 `docs/ABSTENTION.md` 的待办里。

## 7. 局限

- 只在 dev（92 条官方题）上测过；test/holdout 没跑（避免调参污染）。
- `dense` 单路模式只做了粗映射（余弦×10），适合对照，不建议单独使用。
- RRF 的 `k` 与分数映射都是超参，这次只扫了 10/20/60，没有做系统搜索——按项目的规矩，不在 dev 上继续调。
- 没有做"查询改写后再融合"（RM3 / HyDE），那是另一层，未验证。

## 8. 一句话结论

**默认开 hybrid，回退只需一行 env。** 理由：真实用户是口语提问（41%→50% 的方向），官方式提问只差 1pp（噪声内）；代价是每次查询慢 10 倍（20ms→150ms），对一个政策问答产品可接受。若追求极致延迟或无模型环境，`CLAUSELEDGER_RECALL=bm25` 即回退，且模型缺失时会**自动降级**并把 `searched.recall` 写成 `bm25`。

# 切分与格式体检

> 一句话：**结构自洽性 100%，但它证明不了边界对**。真正抓到的是"漏切"——376 行 `1．`、18 行 `⑴`、少量 `第1条` 从未被当成标题，条款数因此少了 6.2%。格式层面五种载体的零字率全部为 0，双读比 <0.6 的 11 份网页**全部是模板噪声**，没有正文丢失。

## 1. 为什么不能再用检索指标

实验 B 已经把话说死了：三版解析器（v0.3.1 / v0.3.2 / v0.3.2+注释修复）跑同一批 100 条 dev 题，**hit@1 全 54%，top-1 命中文档 0 条变化**。

检索指标问的是"找没找到"，而切分问的是"切没切对"。**一个切错的条款，仍然可能被检索到**——因为它的文本还在。所以必须换一把尺子。

## 2. 尺子一：七条结构不变量

全部机械可判，跑全部 574 份：

| 编号 | 判据 | 违反意味着 |
|---|---|---|
| I1 | 条款文本必须以自己的编号开头 | 切点落在句子中间 |
| I2 | 父条款文本必须包含子条款文本 | 区间算错、漏字 |
| I3 | 子条款区间必须落在父区间内 | 层级归属错 |
| I4 | 同级兄弟区间不相交 | 区间重叠、重复计数 |
| I5 | 叶子区间并集应覆盖全文 | 有正文从未进索引 |
| I6 | 单条 < 15 字视为碎片 | 标题被误认成条款 |
| I7 | 单条 > 3000 字视为粘连 | 该切没切 |

跑之前先修了一个**体检工具自己的 bug**：第一版按 `path` 找父条款，而 `path` 会重复（见 §4.2），结果误报 1,791 条区间越界。改成"按 level 栈找最近的更粗一级"后，违规归零。

## 3. 结果

```
载体           份数     条款    I1标签    I2父含子    I3区间    I4重叠    I6碎片    I7粘连      path重复
html          573  10,742        0         0        0        0       335        8       6,242
pdf-native      1     123        0         0        0        0         6        3          56
```

**I1–I4 全部为 0**：编号自洽、父子包含、区间嵌套、兄弟不重叠。

### 但这个"0"要说清楚

I2 和 I3 **几乎是同义反复**：父条款的终点被定义成"下一个层级 ≤ 自己的标题"，所以它必然包住子条款。这两条能抓的是实现 bug（比如第一版用 path 当主键），**抓不到"边界切错"**。

真正有信息量的是另外三个数：**path 重复、碎片、粘连**，以及下面这一节。

## 4. 三个真发现

### 4.1 漏切：376 行 `1．`、18 行 `⑴` 从来没被当成标题

`tools/ingest/clause.py` 的 `LEVELS` 只认半角句点 `1.`，不认全角 `1．`；不认圈码 `⑴⑵⑶`；不认 `第1条`。

扫全库（排除已识别的标题）：

| 没被识别的编号形态 | 行数 | 例子 |
|---|---|---|
| `1．` 全角句点 | **376** | `1．就业见习基地` |
| `⑴` 圈码 | **18** | `⑴创业企业获得科技企业孵化器…`（教委 72 分表） |
| `1、` 顿号 | 4 | `3、2009年，对非上海生源…` |
| `第1条` 阿拉伯 | 少量 | — |

**后果不是"少几个条款"，是"整段并进上一条"**：`沪人社规〔2017〕22号` 的三级条目全部粘在 `三、/（一）` 下面，检索命中时引用只能指到 `三、`。

修复后重解析 574 份（从 `data/raw` 原件，不发 HTTP，335 秒）：

| | 修前 | 修后 | 变化 |
|---|---|---|---|
| 条款总数 | 10,233 | **10,837** | +604（+5.9%）；含补全角句点 +632、再减去尾部清洗 -28 |
| 索引叶子条款 | 6,072 | **约 6,360** | +288（重建后实测） |
| `沪人社规〔2017〕22号` | 27 | **29** | 新增 `三、/（一）/1．/（1）` 这类 |

### 4.2 path 不唯一：6,242 条条款的路径会撞

`path` 是"编号路径"（`一、/（一）/1.`）。问题是**同一份文件里编号会重来**：通知正文用一套 `一、二、三、`，附件《办法》又从 `一、` 开始。

实测：**205 份文档、6,242 条条款 path 重复**（占全部条款 57%）。

后果：
- 引用文案 `《沪人社规〔2024〕5号》一、` **指不到唯一一条**；
- 代码里若用 path 当键（比如按 path 找父条款），会认错父节点。

现在的缓解是引用**同时带偏移**（`第 N 段第 M 字` 或 `第 N 页`），path 只作人类可读的层级说明。彻底修需要给 path 加"第几处"后缀，或者把主键换成 `(doc_no, start)`——**这会影响所有引用文案，先记为已知问题**。

## 5. 尺子二：双读一致性（五种载体）

同一份字节，用两个独立读取器各读一遍，比中文字数：

| 载体 | 单元 | 零字率 | 中位字数 | 双读比中位 | <0.6 |
|---|---|---|---|---|---|
| html | 573 | **0%** | 836 | 0.91 | 11 |
| pdf-native | 122 | **0%** | 1,125 | **1.00** | 0 |
| pdf-ocr | 103 | **0%** | 950 | —（无第二读） | — |
| docx | 12 | **0%** | 216 | **1.00** | 0 |
| doc | 59 | **0%** | 248 | —（同一工具） | — |

html 的第二读是 BeautifulSoup 全文，PDF 文本层是 pypdf vs pdfium，docx 是 python-docx vs textutil。

**11 份 <0.6 的网页逐份查过**：缺失的行全是「您现在的位置 / 发布时间 / 相关稿件 / 政府网站标识码 / 公安网安备」，以及同一正文在页面里重复 2–3 份（响应式布局的移动端副本）。**没有一份丢正文**。

一个典型：`沪劳保发〔1998〕19号` 第二读 665 字、我们 125 字——差的全是导航和"相关稿件"列表里**别的文件的标题**。

## 6. 体检的盲区（必须写出来）

1. **I2/I3 是同义反复**，只能抓实现 bug，抓不到边界对错。
2. **.doc 没有独立第二读**——我们的读取器本身就是 `textutil`，双读比恒为 1，等于没测。
3. **OCR 没有第二读**。扫描件只有 Vision 一个读器，错字只能靠人工看。已知：`ocr_conf` 中位 0.8 左右。
4. **"边界对不对"没有金标准**。现在只有一个 I1（是否以编号开头）能间接反映切点位置。要真判，得人工标 20 条边界——还没做。
5. **0 条款的 56 份没被这张表区分**：其中 38 份是延期清单/表格型通知（判 0 条款正确），其余是短通知（无编号，按段落入索引）。

## 7. 对评测的影响

修完重跑 dev（同 121 条）：

| 指标 | 修前 | 修后 |
|---|---|---|
| official hit@1 | 54% | **53%**（43–62%） |
| official hit@3 | 62% | **64%** |
| MRR | 0.60 | 0.60 |
| 应答率 | 80% | **78%** |

条款变细，有 2 条题从"答"变成"拒"（覆盖率闸没够）。**hit@1 掉 1 个点、hit@3 涨 2 个点**——再次说明检索指标对切分改动几乎不敏感，这就是为什么结构指标必须单独报。

## 8. 下一步

1. **人工标 20 条边界**（每条给"上边界/下边界对不对"），这是唯一能验证 §6.4 的办法。
2. path 唯一化方案定夺：加"第几处"后缀 vs 换主键。
3. OCR 找一个第二读做交叉校验（比如 PaddleOCR 与 Vision 的字符一致率）。

## 0. 先用现有数据说明：为什么"50 题 + hit@1"这套不够用

现状（`eval/reports/20261112-002724.md`）：

| 类别 | n | hit@1 | hit@3 | MRR@10 | 首条现行 | 拒答 |
|---|---|---|---|---|---|---|
| literal | 20 | 90% | 100% | 0.94 | — | — |
| paraphrase | 10 | 10% | 10% | 0.10 | — | — |
| version | 5 | 100% | 100% | 1.00 | **60%** | — |
| out_of_scope | 15 | — | — | — | — | 100% |

四个硬伤，每一个都能用上面的数字直接指认：

1. **规模不够看见要看的效应。** test split 只有 20 题，配对设计下最小可检测效应（MDE）约 **25 个百分点**；50 题全用也只有 **15pp**（σ_d=0.38）。也就是说，现在这套题**只能发现灾难性回退，不能证明 5–10pp 的改进**。第 1 节给公式与表。
2. **指标测的不是产品承诺。** `tools/eval_retrieval.py` 的 `rank_of()` 是"标题子串命中"，即**文档级**；产品承诺是"条款 + 页码 + 现行版本"。后果已经出现：version 题 hit@1=100%，但首条是**已失效版本**的占 40%——按现行指标，给出 2015 年旧文件算"命中"。
3. **题目与语料同源，构成泄漏。** 实测：20/20 条 literal 题，其 `expect_title_kw` **全部**逐字出现在问题里（脚本见附录 A.3）。金标是从标题反推的，BM25 必然命中。这个 90% 不能作为"能力证据"，只能作为"回归护栏"。
4. **失败无法归因。** 9 条未命中**全部是 paraphrase 且全部是"拒答"**——失败在闸门，不在排序；但指标只报 hit@1，看不出该修闸门还是该修排序。

下面 6 节分别给出可执行的修法，每节末尾是可以直接抄进规范的条文（R 编号）。

## 1. 测试集规模：n 要多少，n=50 能看见多大的效应

### 结论

**配对设计、α=0.05、power=0.80 下：检测 5pp 需要 ≈280–460 题，10pp 需要 ≈110–130 题，15pp 需要 ≈50 题。n=50 的 hit@1 的 MDE 是 15.4pp，n=20（现 test split）是 25.1pp——现在这套题证明不了 5–10pp 的改进。**

### 依据

Sakai 的 topic set size design 给出可直接套用的设计流程：先规定效应量 δ 与总体标准差 σ（或配对差的标准差 σ_d），再用 t 分布迭代求 n，使检验达到指定功效；论文同时给出 two-sample、paired、ANOVA 三类设计的公式与查表，并指出 IR 领域长期沿用 TREC 的 50/100 topics 是惯例而非统计论证。

- Sakai, *Topic Set Size Design*, Information Retrieval Journal 19(3), 2016 — https://link.springer.com/article/10.1007/s10791-015-9273-z
- 会议版：ICTIR 2016 — https://dl.acm.org/doi/10.1145/2970398.2970443

**（1）均值型指标（MRR / nDCG）——配对 t**

```
n = ( t_{n-1, 1-α/2} + t_{n-1, 1-β} )² · σ_d² / δ²          （t 随 n 迭代，2~3 轮收敛）
MDE(δ) = ( t_{n-1, 1-α/2} + t_{n-1, 1-β} ) · σ_d / √n
```

表 1-1 配对设计所需题数（双侧 α=.05，power=.80；行 σ_d，列 δ）

| σ_d \ δ | 5pp | 7.5pp | 10pp | 15pp |
|---|---|---|---|---|
| 0.20 | 128 | 58 | 34 | 16 |
| 0.25 | 199 | 90 | 51 | 24 |
| 0.30 | 285 | 128 | 73 | 34 |
| 0.35 | 387 | 173 | 99 | 45 |
| 0.40 | 505 | 226 | 128 | 58 |
| 0.50 | 787 | 351 | 199 | 90 |

> 注：同为 10pp，独立样本设计约需上表的 **2 倍**（因为配对消掉了题目难度方差）。我们的设计天然是配对的（同一批题跑两个版本），没有理由按独立样本算。

**（2）n 给定时能看见的最小效应**（80% power）

表 1-2

| n | σ=.25（MRR） | σ=.30（nDCG@10） | σ=.38（hit@1） |
|---|---|---|---|
| 20（现 test split） | 16.5pp | 19.8pp | **25.1pp** |
| 50（现全集） | 10.1pp | 12.1pp | **15.4pp** |
| 100 | 7.1pp | 8.5pp | 10.8pp |
| 200 | 5.0pp | 6.0pp | **7.6pp** |
| 300 | 4.0pp | 4.9pp | 6.2pp |

σ_d 的经验值：hit@1 这类 0/1 指标，若基线命中率 p≈0.8，σ≈√(p(1-p))=0.40；p≈0.6 时 0.49；但我们测的是**同一题两个版本的差值**，差值方差通常小于边际方差，实测常在 0.25–0.40。**第一版必须实测 σ_d 再回填这张表**（附录 A.2 给了脚本）。

**（3）比例型指标（hit@k）——用不一致对算，比均值公式更省题**

二值指标不该套 t 公式，应该用 McNemar 的样本量公式（Connor 1987 同式）：

```
n = [ z_{1-α/2}·√(p01+p10) + z_{1-β}·√( p01+p10-(p10-p01)² ) ]² / (p10-p01)²
p10 = 只有新版本命中的比例，p01 = 只有旧版本命中的比例，δ = p10-p01
```

表 1-3

| δ | p01=.02 | p01=.05 |
|---|---|---|
| 5pp | 281 | 469 |
| 10pp | 108 | 155 |

两式并不冲突，只是参数化不同（σ_d² = p01+p10-δ²）。同一 δ=10pp：若实测 σ_d=0.30（等价 p01+p10≈0.10），两式给出 73 与 77；表 1-3 的 108 对应 p01=.02、p10=.12（σ_d≈0.36），155 对应 p01=.05、p10=.15（σ_d≈0.44）。**规范做法：均值型先实测 σ_d 用表 1-1，比例型先估 p01/p10 用表 1-3，不要拿不同假设的默认值互相比较。**

**（4）n=50 时"显著"到底有多难**

精确 McNemar 双侧 p（b=新对旧错，c=旧对新错）：

| b:c | p | 结论 |
|---|---|---|
| 5:0 | .0625 | 不显著 |
| **6:0** | **.0313** | 显著 |
| 7:0 | .0156 | 显著 |
| 8:1 | .0391 | 显著 |
| 9:1 | .0215 | 显著 |
| 10:2 | .0386 | 显著 |
| 6:1 | .1250 | 不显著 |

即：50 题里必须出现 **6 个"只在新版命中"且旧版一个都不掉**，才算 p<.05；一旦有 1 条回退，就要 8:1 才够。**这就是"20 题 test"在实际中几乎不可能显著的原因。**

**（5）按类别分配，而不是平均分配**

| 类别 | 现状 | 目标 | δ | 需要 n | 200 题方案给 | 该 n 下 power |
|---|---|---|---|---|---|---|
| paraphrase | 10% | 40% | 30pp | 28（McNemar） | 60 | **0.99** |
| version（首条现行） | 60% | 80% | 20pp | 45 | 40 | 0.78 |
| literal | 90% | 95% | 5pp | **281** | 50 | 0.21 |
| out_of_scope | 15/15 | 误答率<5% | — | 59（零失败上界） | 50 | 上界 5.8% |

读法：
- **paraphrase 是最值得投题量的类别**：现状 10%，修好闸门后到 30–40% 是现实目标，60 题就能 99% 检出。
- **version 只要 40 题**就能测 20pp 的改进，且它对应"给错版本"这种真实事故，必须单列指标。
- **literal 不要追 5pp**：要 281 题才测得出来，成本是 paraphrase 的 5 倍，收益只是"从 90% 到 95%"。literal 只做**回退护栏**（n=50 时 15pp 的回退一定能抓到）。
- **out_of_scope 用"零失败上界"**：n 条全对时，真实误答率的 95% 上界 = 1-0.05^(1/n)。n=15→18.1%，n=29→9.7%，n=50→5.8%，n=59→5.0%。**要对外声称"误答率<10%"，至少 29 条；声称<5%，至少 59 条。**

### 对我们的具体建议

- **R1.1** 评测集总量定为 **200 题**：literal 50 / paraphrase 60 / version 40 / out_of_scope 50。分配依据是上表的目标效应量与成本，不是均分。
- **R1.2** 在 `eval/FROZEN.json` 里写明"设计功效"：主指标 = paraphrase 类 hit@1，δ=0.30，n=60，power=0.99；次要指标各自标注 MDE（按表 1-2 与当时实测 σ_d 计算）。
- **R1.3** 任何"提升 X 个百分点"的对外结论，必须先给出该指标的 MDE；**X < MDE 时只能写"未见显著差异"，不能写"提升"**。
- **R1.4** 汇总指标（全类别合并）必须按类别加权或分层报告，禁止把 4 个类别直接平均（现报告没有合并列，这是对的，保持）。
- **R1.5** 首版跑完后，用附录 A.2 脚本实测 σ_d，回填表 1-2，并把实测 σ_d 写进 `eval/FROZEN.json` 的 `design` 字段，供下一版估算。

## 2. 抽样与偏置：单系统 pool 是自我实现的预言

### 结论

**单系统 pooling 的池就是被测系统的输出，池外文档一律按不相关计——这会让 recall 与 hit@k 系统性虚高，并且惩罚任何"召回了以前没召回的条款"的改动；再叠加"出题关键词来自标题"，评测就变成了循环论证。缓解手段很便宜：加深池、加多路召回、加 query-by-document、加人工补池。**

### 依据

- Cranfield/depth-k pooling 的标准定义：由若干 run 的 top-k 并集作为判定池，**池外文档一律视为不相关**；由此导致 recall 被低估、以及"复用旧池评新系统"的 pool bias（Zobel 1998；Buckley et al. 2007；Webber & Park 2009；Lipani et al. 2016 均有讨论）——见 Active Sampling 一文的第 1 节综述：https://arxiv.org/abs/1709.01709
- Zobel, *How Reliable Are the Results of Large-Scale Information Retrieval Experiments?*, SIGIR 1998 — https://dl.acm.org/doi/10.1145/290941.291014
- TREC DL 的做法可以直接对照：**depth-10 的浅池 + HiCAL 主动选样补判**，并明确写了"HiCAL 不依赖 runs 作为文档来源"这一设计动机——这正是为了消掉"池由系统决定"的偏置：https://arxiv.org/abs/2104.09399

### 具体到我们，偏置有四层

1. **池偏（pool bias）**：池 = BM25 top-k。BM25 漏掉的正确条款，永远进不了池，永远算"不相关"。更糟的是：某次改动（加同义词、调 k1/b、改分词）召回了新的正确条款，它**没被判过 → 按不相关算 → 指标下降**。系统会因此"学会"不去改进。
2. **查询—语料泄漏**：literal 题 20/20 的关键词逐字出现在问题里（附录 A.3 实测）。这不是"题目简单"，是**金标标识符就是查询的一部分**，BM25 词面匹配必然命中。它测的是"分词器能不能对上原文"，不是"能不能找到政策"。
3. **难度选择偏置**：题目只从"系统能答的"里出（或出题人下意识只写自己有把握的），难度分布整体左移，绝对分数虚高，且**上限饱和**（literal 已 90%，再优化没有分辨力）。
4. **拒答题的判定方式**：`not hits` 即算"正确拒答"。系统只要少召回，就能同时拿到"高拒答正确率"和"低覆盖率"——两个指标方向相反，却没被联合约束。

### 低成本缓解（按性价比排序）

1. **多路 pool（几乎零成本）**：同一批题，用 ≥6 个配置各取 top-20 求并集：
   BM25(k1=0.9,b=0.5)、BM25(k1=1.2,b=0.75)、BM25(k1=1.5,b=0.9)、title-only BM25、char-bigram BM25、规则/关键词召回。并集人工判。这一步能把"池 = 单一系统输出"变成"池 = 六种系统输出"。
2. **query-by-document 补池**：拿金标条款原文前 200 字当查询，取 top-20 并入池。它能捞出"换了说法但讲同一件事"的条款——正是 paraphrase 类最需要、而 BM25 最抓不到的。
3. **人工补池（每题 3 分钟）**：出题人在语料里手工搜关键词 + 浏览相邻条款，把找到的正确条款加入池；把"人工补入条数"记进判断题文件，作为**池完备度的代理指标**（持续为 0 说明池可能没问题；经常 >0 说明池在漏）。
4. **加深池**：语料只有 5,736 条，判定成本是线性的，**没必要学 TREC DL 只判 depth-10**。建议 depth=20（200 题 × 20 = 4,000 次判定，人工约 3–5 人日）。这是小语料相对 TREC 的优势，应当用掉。
5. **分层抽样**：按 业务域（社保/就业/人才/劳动关系/工资福利）× 年代段（1996–2005/2006–2015/2016–2020/2021–2026）× 问法（literal/paraphrase/version/oos）分层，保证每格 ≥3 题；并保证 560 份文件里**至少 120 份**被某道题的正例覆盖（覆盖率审计，附录 A.4 给了检查脚本）。
6. **拒答题两路构造**：一路"域外"（北京政策、税务、公积金非人社事项）测城市闸/领域闸；一路"域内但语料无覆盖"（1998 年已废止文件的细节、尚在征求意见稿阶段的事项）测证据不足闸。两路的误答要分开报。

### 对我们的具体建议

- **R2.1** 每题的判定池 = 6 路召回并集（附表配置）+ query-by-document top-20 + 人工补池；池深 ≥20。判定文件记录 `pool_sources` 与 `manual_added`。
- **R2.2** 出题阶段**禁止看检索结果**：出题人只读政策原文与官方问答，写完题后再单独跑召回补池；出题记录 `authored_without_system: true`。
- **R2.3** 任何"新召回条款"若在旧池外，判定时必须补判，不能直接按不相关计；在 `eval/CHANGELOG.md` 记录补判条数。
- **R2.4** 拒答题的"正确"定义为：`refuse_reason ∈ {证据不足, 不在覆盖范围}` 且**同时**满足"该题在语料中确实无 grade≥2 的条款"（由人工确认，不靠 `not hits` 推断）。
- **R2.5** 每年做一次覆盖率审计：随机抽 40 份未被任何题覆盖的文件，人工判断"是否值得出题"，若 >25% 值得，则说明选题偏了，需补题。

## 3. 题目来源：真实日志 > 官方问答 > 人工改写 > LLM 从文档生成

### 结论

**LLM 生成的 query 会系统性高估检索效果（更长、更"好搜"、相关文档更少），对 BM25 这种词面匹配系统高估尤甚；拿到真实日志前，最接近真实的构造是"官方政策问答 + 真实搜索下拉词"，并且保留原始措辞、不做润色。**

### 依据

- 真实分布长什么样：MS MARCO 的 1,010,916 条问题全部来自 Bing 查询日志（真实用户、真实口语、带错别字）——https://arxiv.org/abs/1611.09268 ；DuReader 的问题来自百度搜索与百度知道，明确包含 yes-no 与 opinion 类型，说明中文用户提问并不总是"事实型"——https://arxiv.org/abs/1711.05073
- 合成 query 会不会偏：SIGIR 2024 的对照实验（TREC DL 2023 上）给出三条可直接引用的观察：GPT-4 生成的 query **明显长于**真实 query、T5 生成的更短；**合成 query 的相关文档数远少于真实 query**；**所有系统在合成集上都拿到更高的分数**，作者结论是"合成集更容易，会高估系统性能"，同时**没有**发现对 LLM 系统的系统性偏袒——https://arxiv.org/abs/2405.07767
- 偏差影响的是绝对值还是排序：对合成数据的偏差分析显示，偏差对**绝对性能**影响显著、对**相对比较**影响较小（因此可用于 A/B 排序，不可用于对外报绝对分）——https://arxiv.org/abs/2506.10301
- 从文档生成问题是 RAG 评测的通行做法（RAGAS 即从文档生成问题）——https://arxiv.org/abs/2309.15217 ，但它测的是"给定文档能不能答"，不是"用户能不能找到"，**不能直接拿来当检索评测集**。

**为什么对我们尤其严重（推论，需自测验证）**：生成器看过条款原文，会把"生育津贴""劳动合同期满终止"这类术语写进问题；而真实用户说"老婆生孩子能休多久""合同到期了还能不能要补偿"。BM25 是纯词面匹配，术语重合直接决定命中。所以合成题会**掩盖**现在 paraphrase 只有 10% 这个最严重的问题——这恰好是我们最需要测的地方。

### 拿不到真实日志时的替代构造（按"接近真实"的程度排序）

1. **官方政策问答（最接近，且出题人不是我们）**：上海人社局"政策解读"栏目里的"《XX 通知》政策问答"，格式为编号问句 + 答 + 文号，单篇 5–8 组，全站约 323 篇、可抽出 1,500–2,500 组，过滤到 560 份语料覆盖范围后约 300–600 条可用。入口：https://rsj.sh.gov.cn/tzcjd_17352_17352/ ；栏目索引另见 https://rsj.sh.gov.cn/tzcjd_17351/index.html 。这类问题**由政策制定方撰写、面向公众**，措辞接近真实咨询，且自带文号可映射到条款。详见 `docs/eval-datasets-research.md` 的方案 A。
2. **搜索下拉词（最接近"口语"，可批量）**：百度下拉 API 实测可用，返回的是真实用户的搜索续写：
   `https://www.baidu.com/sugrec?prod=pc&wd=社保断缴` → `{"q":"社保断缴","g":[{"q":"社保断缴有影响吗"},{"q":"社保断缴可以补缴吗"},{"q":"社保断缴怎么办"},{"q":"社保断缴多久不能用"},…]}`
   做法：对 560 份文件各取 3–5 个核心术语做种子，批量拉取，得到数千条真实问法，再人工筛到人社领域、映射到条款。**这是当前性价比最高的口语 query 来源**，且完全不经过我们的系统。
3. **信访/留言类问句**：中国政府网"人民群众留言入口" https://liuyan.www.gov.cn/hudong/atwls/rmqz.htm （真实群众提问，需按主题筛）；上海人社"互动交流" https://rsj.sh.gov.cn/thdjl_17597/index.html 。
4. **人工改写（补分布，不补内容）**：取官方问答的 300–600 条，交给**不写代码、也看不到检索结果**的同学改写成 2–3 种口语问法（"老婆生孩子能休多久"这种），金标沿用官方答案。改写者的任务是"换说法"，不是"编新题"。
5. **LLM 生成（只做变体，不做新题）**：仅用于把一条已有问题扩成 N 种口语变体，且**必须**：① 不给模型看条款原文；② 生成后由人删掉任何与条款标题重合 ≥3 字的表述；③ 100% 人工过一遍。LLM 不得用于"从文档出题"。

**建议配比（200 题）**：真实日志/官方问答 50%（100 题）、人工改写 30%（60 题）、LLM 变体 20%（40 题，且全部人工复核）。`source` 字段按 `docs/EVAL.md` 的优先级记：`official_qa > user_confirmed > manual > llm_variant`。

### 对我们的具体建议

- **R3.1** 每题必带 `source` 与 `source_url`；`llm_variant` 占比不得超过 20%，且必须 `human_verified: true`。
- **R3.2** 出题人**不得**在写题时打开检索界面或看 `eval/reports/` 的命中列表；违反则该题作废。
- **R3.3** 每季度做一次"来源审计"：随机抽 20 题，判断"这句话像不像真人会问的"，若 <70% 判"像"，说明题面书面化，需追加口语改写。
- **R3.4** **禁止**用 LLM 从条款原文生成问题作为正式评测题；允许用于"扩充同一问题的问法"，但必须过 R3.3 的审计。
- **R3.5** 建立"真实问句池"：把下拉词、官方问答、留言里**暂时映射不到条款**的问句也存下来（`unmapped` 标记），它们是下一版语料扩充与拒答设计的输入，不要丢。

## 4. 统计方法：配对、区间、多重比较、报告格式

### 结论

**二值指标（hit@1/hit@3/拒答对错）用精确 McNemar，报 b/c 与 p；均值型（MRR/nDCG）用配对 bootstrap（BCa，10k 次）；单比例用 Wilson；配对差用 Newcombe 或 bootstrap；多个指标/类别用 BH-FDR 校正；每次评测预注册 1 个主指标，其余标"探索性"。**

### 依据

- McNemar 检验（配对二值）：McNemar, *Note on the sampling error of the difference between correlated proportions or percentages*, Psychometrika 12(2), 1947 — https://doi.org/10.1007/BF02295996 。样本量小（b+c<25）时用**精确**版本，不要用 χ² 近似。
- Wilson 区间在小样本、极端比例下明显优于 Wald：Wilson, *Probable Inference…*, JASA 22, 1927 — https://doi.org/10.1080/01621459.1927.10502953 。现报告已在用 `wilson()`，保持。
- 多重比较：Benjamini–Hochberg FDR，JRSS-B 57(1), 1995 — https://doi.org/10.1111/j.2517-6161.1995.tb02031.x
- 检验选择错误（该配对却用独立、该校正却不校正）会同时抬高 Type I 与 Type II 错误：arXiv 1905.11096 — https://arxiv.org/abs/1905.11096
- **不要用 LLM 当判官替代人工判定**：可以构造出专门"骗过判官"的系统把分数刷上去，且判官与生成模型存在循环性——https://arxiv.org/abs/2412.17156

### 怎么选（决策表）

| 指标形态 | 点估计 | 区间 | 两版本比较 |
|---|---|---|---|
| 单比例（本版 hit@1=18/20） | k/n | **Wilson** | — |
| 二值、配对（同题两版） | p10-p01 | Newcombe 配对法或配对 bootstrap | **精确 McNemar**（报 b/c） |
| 均值、配对（MRR/nDCG） | 均值差 | **配对 bootstrap BCa，10k 次** | 同左，看 CI 是否跨 0 |
| 两个独立比例（如两类题难度） | 差值 | Newcombe 独立法 | 卡方/Fisher（少用） |

选择理由：hit@1 是 0/1，每题只有"对/错"，两版之间的信息全部在**不一致对**（b、c）里，McNemar 正好只用这部分，效率最高；MRR/nDCG 是连续值，分布偏斜且样本小，bootstrap 不依赖正态假设。

### 多重比较

一次评测会同时看 4 个类别 × 2–3 个指标 = 8–12 个比较。做法：
1. **预注册 1 个主指标**（建议：paraphrase 类 hit@1），主指标用 α=.05 不校正，结论以它为准。
2. 其余标"次要/探索性"，用 **BH-FDR q=.05** 校正后再下结论。
3. 报告里把"校正后仍显著"与"仅未校正显著"分开写。

> 现状提醒：现在 paraphrase 10 题、literal 20 题、version 5 题，任何跨类别的"谁更好"比较都在 n=5–20 上做，**连校正的前提都不成立**——样本量不够时不谈多重比较，直接说"样本不足以比较"。

### 最小充分报告格式

每次评测**必须**有这么一张表（一类别一行，主指标加粗；下表数值为格式示例，非真实结果）：

| 类别 | n | 指标 | 本版 | 95% CI | 基线 | Δ | Δ 的 95% CI | 配对检验 | b/c |
|---|---|---|---|---|---|---|---|---|---|
| paraphrase | 60 | **hit@1** | 41.7% (25/60) | 30.1–54.3 | 10.0% | +31.7pp | +20.1–+43.9 | McNemar p<.001 | 21/2 |
| paraphrase | 60 | MRR@10 | 0.46 | 0.37–0.55 | 0.10 | +0.36 | +0.27–+0.45 | bootstrap p<.001 | — |
| version | 40 | 首条现行率 | 80.0% | 65.2–89.5 | 60.0% | +20.0pp | +3.1–+36.9 | McNemar p=.039 | 9/1 |
| out_of_scope | 50 | 误答率 | 2.0% | 0.4–10.5 | 0% | +2.0pp（回归） | — | — | 1/0 |

外加一行元数据：`eval_version`、`sha256`、`commit`、`跑测时间`、`判定人`、`σ_d 实测值`。

**禁止出现在报告里的东西**（现状报告需要删/改的）：
- 没有区间的百分数（"hit@1 90%"单独出现）；
- 三位小数的 MRR（0.94 可以，0.9417 不行——n=20 时第三位没有意义）；
- 跨 eval 版本的绝对值对比（换了题就不可比，只能比"同一版本上的两版系统"）；
- 只报最好的类别，或把 4 个类别平均成一个数；
- 把"覆盖率"当"准确率"（覆盖率 96% 不代表答对了 96%）；
- 把单条 case（"某题答对了"）当能力证据；
- 用 p 值大小代替效应量（p=.03 不等于提升大）。

### 对我们的具体建议

- **R4.1** 主指标固定为 **paraphrase hit@1**（条款级，见第 5 节），预注册在 `eval/FROZEN.json`；改主指标须走 CHANGELOG 并说明理由。
- **R4.2** 二值一律精确 McNemar，报告必含 b/c 与 p；b+c<25 时禁止用 χ² 近似。
- **R4.3** 均值型一律配对 bootstrap BCa 10,000 次，报告 Δ 的 95% CI；CI 跨 0 即判"无差异"。
- **R4.4** 单比例一律 Wilson；n<30 时同时给"零失败上界"（1-0.05^(1/n)）。
- **R4.5** 次要指标 BH-FDR q=.05；报告中区分"校正后显著"与"仅未校正显著"。
- **R4.6** 报告模板固化为 `eval/reports/TEMPLATE.md`，缺字段视为评测无效。

## 5. 判据：三级相关 + 独立"可答性"，金标要能被质疑

### 结论

**用 0/1/2 三级判据 + 一个正交的"可答性"标签；≥20% 双人盲标并报 κ 或 α；金标错误率用"抽检 100 条 + 第二人盲标"估计，并做翻转敏感性分析；LLM 只能预标注，不能定稿。**

### 依据

- 分级判据是 nDCG 的前提（TREC DL 用 0–3 四级）——https://arxiv.org/abs/2104.09399 ；二值只能算 hit@k 与 MAP，表达不了"这条只是相关、不是答案"。
- 换标注者会改变绝对分数：SIGIR 2025 复现 Voorhees(2000) 的重标注实验，发现**系统排序基本稳定，但绝对 nDCG 下降，部分模型排名大幅变动**，并据此提出"test collection 会过期"——https://arxiv.org/abs/2502.20937
- 金标本身会错：对 10 个常用数据集的审计估计，测试标签平均错 **≥3.3%**，ImageNet 验证集 **≥6%**；在算法标记的候选中，**51%** 经众包确认确为错标——https://arxiv.org/abs/2103.14749 。含义：**任何"人工判过"的金标都该假定有 3–6% 的错**。
- κ 的分级惯例：0.41–0.60 moderate、0.61–0.80 substantial、0.81–1.00 almost perfect — Landis & Koch, Biometrics 33(1), 1977 — https://doi.org/10.2307/2529310
- α 的惯例：α≥.80 为可靠，.667–.80 仅可用于探索性结论 — Krippendorff 的常引标准，见 Hayes & Krippendorff, *Answering the Call for a Standard Reliability Measure for Coding Data*, Communication Methods and Measures 1(1), 2007 — https://doi.org/10.1080/19312450709336664
- LLM 判官可被针对性刷分、且与生成端存在循环性：https://arxiv.org/abs/2412.17156

### 判据设计

**两个正交标签，不要合成一个：**

```jsonc
{
  "query_id": "p-012",
  "doc_no": "沪人社规〔2021〕35号",
  "clause_path": "第三条",
  "grade": 2,              // 2=直接回答；1=相关但不足以单独回答；0=不相关/错误条款
  "answerable": "yes",     // yes | partial | no —— query 级字段：该问题在语料范围内是否可答；判定表冗余一份，以 queries 表为准
  "status_at_judgment": "现行",  // 现行 | 已废止 | 已修订 | 未知
  "judge": "A",
  "blind": true,
  "date": "2026-11-12",
  "note": "第二条给标准，第三条给申领流程，本条是标准"
}
```

- `grade` 回答"这条条款是不是这个问题的答案"；
- `answerable` 回答"这个问题在我们的语料范围内有没有答案"——**拒答题的对错由它判定，不由"系统有没有返回"判定**（修掉 §2 的第 4 层偏置）。
- 对 version 类，额外要求 `status_at_judgment`，并单列指标"首条现行率"。

**指标映射**（写进 `app/eval/metrics.py`）：
- `hit@1` = 首条 `grade==2`；
- `hit@3` = 前 3 条中存在 `grade==2`；
- `nDCG@10` = 增益 `2^grade - 1`（0/1/3），折损 `1/log2(i+1)`；
- `首条现行率` = 首条 `grade==2 且 status==现行`；
- `误答率` = `answerable==no` 的题里，系统未拒答的比例；
- `拒答精确率` = 系统拒答中，`answerable==no` 的比例。

**标注流程：**
1. 一标全量（1 人），二标抽 **20%（≥30 条）**，盲标（看不到一标结果）。
2. 算 κ（两两）或 α（多人、有序）：grade 用**加权 κ（线性权重）**，`answerable` 用普通 κ。
3. κ<.60 → 判据有歧义：先改判据文档、再全量仲裁，**不要**直接取平均。
4. 冲突由第三人仲裁，仲裁结果进 `adjudicated: true`。

**金标错误率估计（每次大版本做一次）：**
1. 从已判定条目里随机抽 100 条（按 grade 分层：2/1/0 各 1/3）。
2. 第二人盲标，不许看原判。
3. `error_rate = 不一致条数 / 100`，报 Wilson 区间。
4. **翻转敏感性分析**：把 grade=2 的条目随机翻转 `error_rate` 比例成 0，重算主指标；若结论（显著/不显著）翻转，则说明效应在噪声内，必须加题或改判据。
5. 结果写进 `eval/FROZEN.json` 的 `gold_error_rate` 字段，并在报告里引用。

### 对我们的具体建议

- **R5.1** 判据用 0/1/2 三级 + 正交的 `answerable ∈ {yes,partial,no}`；禁止用单一 0/1。
- **R5.2** 每题判定池 ≥20 条（见 R2.1），判定记录必须含 `judge/blind/date/note`。
- **R5.3** 双标比例 ≥20% 且 ≥30 条；报加权 κ（grade）与 κ（answerable），阈值 κ≥.61；低于则先修判据再重标。
- **R5.4** 每个大版本抽检 100 条估金标错误率，报点估计 + Wilson 区间，并做翻转敏感性分析；`error_rate>10%` 触发判据重审。
- **R5.5** LLM 只可用于"预标注/候选排序"，最终标签必须有人签字；被 LLM 标过的条目在 `judge` 字段注明 `llm_prelabel`。
- **R5.6** version 类题必须绑定 `as_of` 日期（沿用 `docs/EVAL.md` 的口径）；政策更新后该题标 `stale` 并重判，不能沿用旧判定。

## 6. 冻结与版本：怎么防"把 test 背下来"

### 结论

**dev / test / holdout 三段分离（建议 80/80/40），test 每年最多用 2 次、holdout 每年 1 次且由非开发者保管；只追加不删除（用 retire 标记）；设定 5 条明确的"重建触发线"，到线就换版本号，且跨版本不比较绝对值。**

### 依据

- 复用 test set 会带来 iteration / selection bias，TREC DL 专门写了"不要过拟合 test"的最佳实践，并用 dev 集做决策验证其可预测性——https://arxiv.org/abs/2104.09399
- 集合会"过期"：重标注后绝对分数下降、部分系统排名变动，作者明确说"test collections can expire"——https://arxiv.org/abs/2502.20937
- 基准饱和后应重建：GLUE 被推到超过非专家人类水平后，社区另建 SuperGLUE——https://arxiv.org/abs/1905.00537
- 金标错误率是持续存在的（≥3.3%），因此"冻结"不等于"正确"——https://arxiv.org/abs/2103.14749

### 对现有 `eval/FROZEN.json` 的评价

已经做对的四条（test 只发版前跑一次、改用例写 CHANGELOG、只许追加、指标必须带区间并配对比较）**保留**，这是很好的起点。缺的是：
1. 没有**持有人分离**（test 由写代码的人保管，等于没有 holdout）；
2. 没有**过期/重建机制**（题会随政策失效，也会被"背下来"）；
3. 没有 **dev/test 泄漏防护**（现在 dev 30 / test 20，同一人同一批出，很可能已经互相污染）；
4. 没有**金标错误率**字段（第 5 节）；
5. 没有**版本号语义**（`eval-v1` 之后怎么升、升了能不能比）。

### 具体方案

**（1）三段划分（200 题）**

| split | n | 谁能看 | 什么时候跑 | 用途 |
|---|---|---|---|---|
| dev | 80 | 开发者随时 | 每次提交 | 调参、回归 |
| test | 80 | 发版前跑，结果只进报告 | 每季度/每次发版 ≤2 次 | 对外结论 |
| holdout | 40 | **非开发者保管**，开发者不可见 | 每年 1 次（或大版本前） | 验真 |

规则：**任何 test 结果被用于调参，该 test 立即降级为 dev**（在 CHANGELOG 记录 `demoted: true`），并从 holdout 补题或新建题。

**（2）冻结内容（扩展现有 FROZEN.json）**

```jsonc
{
  "version": "eval-v2",
  "frozen_at": "2027-01-15",
  "sha256": "…",                       // 题目 + 判定 + 判据文档三者一起算
  "counts": {"literal":50,"paraphrase":60,"version":40,"out_of_scope":50},
  "design": {"primary":"paraphrase_hit@1","delta":0.30,"power":0.99,"sigma_d":0.50},
  "gold_error_rate": {"estimate":0.04,"ci":[0.015,0.09],"n":100},
  "custodian": {"test":"…","holdout":"…"},
  "rules": ["…"],
  "retire": [{"id":"v-003","reason":"政策已更新，旧判定失效","date":"2027-01-10"}]
}
```

**（3）重建触发线（命中任一条就升版本）**

1. **饱和**：主指标 ≥90% 且 95% CI 下界 >85%（题太容易，没有分辨力）；
2. **失效**：连续 2 个版本主指标变化 <2pp（题不再区分系统）；
3. **语料变更**：新增/废止文件累计 >20%，或任一被引文号状态变化；
4. **金标质量**：抽检错误率 >10%；
5. **时间**：距上次冻结满 12 个月。

另加一条硬规则：**每次升版本必须轮换 ≥20% 的题**（retire 旧题 + 新增同类别新题），否则"新版本"只是旧题的重新排列。

**（4）只追加 + retire，不删除**
删题会让历史报告无法复现。用 `status: active|retired`，retired 题保留在文件里但不计入指标；报告注明"本版 retired n 条"。

**（5）跨版本不比较绝对值**
换了题，绝对值不可比（shelf life 的教训）。跨版本只能比"同一版本上两版系统的 Δ"。版本升级当天，用**同一版系统**在新旧两套题上各跑一次，记录"题目难度差"（`calibration_run`），供后续换算参考。

### 对我们的具体建议

- **R6.1** 200 题按 dev 80 / test 80 / holdout 40 划分，split 字段进题目文件，holdout 单独存 `eval/holdout.json` 并由非开发者保管。
- **R6.2** test 每年最多跑 2 次；跑之前先登记"本次要验证的假设"（预注册），跑完不得改假设。
- **R6.3** 任何 test 结果进入调参 → 该 test 降级 dev，并在 CHANGELOG 记录。
- **R6.4** 触发线 5 条写进 FROZEN.json 的 `rebuild_triggers`，每次评测前人工核对一遍。
- **R6.5** 升版本必须轮换 ≥20% 题目；retire 不删除；跨版本只比 Δ 不比绝对值。
- **R6.6** `eval/CHANGELOG.md` 每条记录包含：改了什么、为什么、旧值、谁批准、影响哪些历史报告。

## 7. 最小可行方案：只做 5 件事

如果只允许做 5 件事，按这个顺序：

**① 把 50 题扩到 200 题，按效应量分配（literal 50 / paraphrase 60 / version 40 / oos 50），其中 40 条划为 holdout。**
理由：n=50 的 MDE 是 15pp，n=20 是 25pp，现在这套题连"闸门修好没有"都测不出来。200 题把 MDE 压到 7.6pp，刚好覆盖 5–10pp 的目标区间。
验收：`eval/questions.json` 200 条，`counts` 与设计一致，sha256 入 FROZEN。

**② 把指标从"文档级标题子串"改成"条款级 + 现行版本 + 闸门/排序分离"。**
理由：现在 version 题 hit@1=100% 却有 40% 首条是失效版本——指标在奖励错误行为。必须改成 `hit@1 = 首条 grade==2 且 status==现行`，并单列 `闸门通过率`、`hit@1|已答`、`误答率`。
验收：`tools/eval_retrieval.py` 输出新表；version 类的"首条现行率"成为一等指标。

**③ 出题人与系统分离：出题只读原文、不看检索结果；≥20% 双人盲标并报 κ；抽检 100 条估金标错误率。**
理由：literal 题 20/20 的关键词逐字来自标题，这是泄漏不是能力；没有第二个人，就无法回答"金标本身对不对"（外部审计显示平均 ≥3.3% 标签错）。
验收：每题带 `source/authored_without_system`；κ 与 `gold_error_rate` 进报告。

**④ 统计口径固化：精确 McNemar + Wilson + 配对 bootstrap BCa + BH-FDR，报告用固定模板。**
理由：n 小的时候，错的检验比没有检验更糟；现在报告里的百分数没有区间，读者无法判断 90% 是 70% 还是 97%。
验收：`eval/reports/TEMPLATE.md` 落地；每份报告含 n、点估计、95% CI、Δ 与 Δ 的 CI、b/c、p、eval 版本与 commit。

**⑤ 冻结与重建机制：dev/test/holdout 三段、只追加 + retire、5 条重建触发线、跨版本不比绝对值。**
理由：没有 holdout 的"冻结"只是"暂不修改"；TREC 的经验是 test 会被过拟合，集合也会过期。
验收：FROZEN.json 含 `custodian/rebuild_triggers/gold_error_rate`；CHANGELOG 有第一条记录。

> 这 5 件做完，评测从"自测"变成"可对外引用的测量"：能说清"改进了多少、这个改进有多可信、金标有多可靠、下次什么时候会失效"。

## 附录 A：公式与可复现计算

### A.1 两个核心公式

```
# 配对均值（MRR / nDCG）
n   = (t_{n-1,1-α/2} + t_{n-1,1-β})² · σ_d² / δ²
MDE = (t_{n-1,1-α/2} + t_{n-1,1-β}) · σ_d / √n

# 配对比例（hit@k / 拒答对错），p10=仅新版对，p01=仅旧版对
n   = [z_{1-α/2}√(p01+p10) + z_{1-β}√(p01+p10-(p10-p01)²)]² / (p10-p01)²
```

### A.2 实测 σ_d 并回填 MDE

```python
import statistics as st
# runs: {qid: {"A": 0/1, "B": 0/1}}，同一批题跑两个版本
d = [v["B"] - v["A"] for v in runs.values()]     # 逐题差值，配对
sigma_d = st.stdev(d)                            # MDE 见 A.1：2.8*sigma_d/sqrt(n)
# sigma_d 写回 eval/FROZEN.json 的 design 字段，下一版据此定题量
```

### A.5 精确 McNemar

```python
from scipy.stats import binom
def mcnemar_exact(b, c):
    n = b + c
    return min(1.0, 2 * binom.cdf(min(b, c), n, 0.5))
# 6:0 -> 0.0313 ; 5:0 -> 0.0625 ; 8:1 -> 0.0391
```

### A.6 零失败上界

```
误答率 95% 上界 = 1 - 0.05^(1/n)
n=15 → 18.1% ; n=29 → 9.7% ; n=50 → 5.8% ; n=59 → 5.0%
```

# 端到端漏斗：从一句提问到一张卡，每一步剩多少

一个 `hit@1` 说不清用户为什么没拿到答案。这里把链路拆成 7 步，每步写清分母。
实现：`python -m tools.eval_funnel`（`--paraphrase` 跑口语集）。

## 口径

| 步 | 含义 | 分母 |
|---|---|---|
| S1 覆盖闸 | 题被放进检索（不是提前拒答） | 全部题 |
| S2 召回 | 金标文件在候选前 10 名（放开全部阈值） | 全部题 |
| S3 排序 | 金标文件排第 1 | 全部题 |
| S4 取证 | 卡里的证据引用了金标文件 | 全部题 |
| S5 内容 | 卡里的引文覆盖官方答案（至少一句 / 过半） | 只在「官方答案确实写在该文件里」的题 |
| S6 决策 | 系统真的作答（`kind=ok`） | 全部题 |
| S7 端到端 | 作答 + 引对文件 + 内容覆盖 | 全部题 |

S5 的分母为什么变：官方问答里的答案常常是**编者转述**，不逐字出现在政策原文里。
实测 81 道有官方答案的 dev 题中，只有 **50 道**的答案能在金标文件里找到原文，
5 道只在别的文件里找到（疑似金标挂错），26 道哪里都找不到（转述）。
所以逐字覆盖只能在可核对的子集上算。

## 结果（dev）

| 步 | 官方题 n=114 | 口语题 n=64 |
|---|---|---|
| S1 覆盖闸 | 100% | 100% |
| S2 召回 R@10 | **76%** | 73% |
| S3 排序第 1 | **56%** | 45% |
| S4 卡里引对文件 | 64% | 52% |
| S5 内容覆盖（至少一句） | **39%**（n=56） | — |
| S6 真的作答 | 83% | 58% |
| **S7 端到端** | **43%** | **36%** |

## 怎么读

- **掉得最多的是 S2→S3（76%→56%）**：答案已经在候选里，但有 20pp 排不到第一。
- **第二处是 S5（39%）**：文件选对了，展示的那一条却不是写答案的那条。
- S4（64%）> S3（56%）：因为卡片会给前 3 名各补 2 条同文件条款，金标文件即使不是第一名，也可能被带进证据。
- 端到端 43% 与 hit@1 63% 的差，就是「引对文件」和「答对问题」之间的差。

## 已知不足

- S5 依赖官方答案可核对，口语集完全不适用（`n=0`），所以口语的 S7 退化为「作答+引对文件+排第一」。
- 24 道 v3 新题的金标是自动挂的，尚未人工核对。
- 题目来自官方问答原句，用词与语料同源（泄漏度 38%），绝对值偏乐观。

## 2026-11-20 重测（两处都是"量具"，不是系统）

| 步骤 | 修前 | 卡组装后 | 再补主语 |
|---|---|---|---|
| S1 覆盖闸 | 100% | 100% | 94%* |
| S2 召回 R@10 | 76% | 78% | 78% |
| S3 排第一 | 56% | 57% | **68%** |
| S4 卡里引对文件 | 64% | 70% | 73% |
| S5 内容覆盖 | 39% | **54%**（n=56） | **57%**（n=54） |
| S6 作答 | 83% | 79% | 82% |
| S7 端到端 | 43% | **50%** | **57%** |

\* S1 94% 是因为分母里还留着 7 条 ambiguous 题（标了但没从分母里去掉），
它们的结局是"不该检索"，所以 S1 看起来掉了——不是回归。

两处改动的性质要分清：

1. **卡组装**（`quote()` 短条款整条给、长条款从数字句起、证据上限 5→8）：
   只改展示，S5 +15pp、S7 +7pp。这部分是**真的把已经拿到的内容显示出来**。
2. **题目补主语**（`q_ctx`）：S3 +11pp、S7 +7pp。这部分是**量具修正**——
   原题问"文件从什么时候执行"，系统无从知道指哪份文件，错不在检索。

两件都不能算"检索变好了"。检索（S2）从头到尾是 76%→78%。

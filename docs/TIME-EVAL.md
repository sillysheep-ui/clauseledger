# 时间类评测：同一个问题，年份不同，答案必须不同

## 为什么单独做一套

现有的 94 道 dev 题**一条都不带年份**，所以"时间感知"这个能力在旧题集里测不到——
哪怕把 `as_of` 写成硬编码今天，hit@1 也是 55%，看不出任何差别。

要证明这一层有用，只能用**答案会翻转的题**：同一个问题，问 2019 年和问 2024 年，
正确文件不是同一份。

## 题怎么来的（不是手写，是筛出来的）

1. 按标题归一化分组（去掉年份、文号、届次），得到"同一件事的不同年份版本"。
2. 从 `data/registry/relations.jsonl`（143 条废止/延期关系）给**没写有效期**的文件补结束日：
   被 X 废止 → 结束日 = X 的生效日。
3. 只保留**家族里每个文件都有日期**的组（否则"日期未知"的文件会在任何年份都算有效，年份就白问了）。
4. 在这一组里找"**恰好只有一份有效**"的年份，取最早与最晚两个，间隔 ≥3 年。

筛完剩 19 个干净家族，人工挑 8 对、改写题干成自然问法 → `eval/questions_time.json`（16 题 / 8 对）。

> 第一版筛出 7 对，但没做第 3 步，家族里混着"日期未知"的旧文件；
> 结果 7/7 的题两题返回同一份文件——**不是系统不看年份，是题本身没区分度**。
> 这一步是这次评测里最值钱的教训：**出题时没控制变量，测出来的数字没有意义**。

## 打分只看三件事

| 指标 | 含义 | 为什么要有 |
|---|---|---|
| 单题 hit@1 | 那一年该用的文件排第一了吗 | 常规口径 |
| **成对通过** | 两题都对才算这对成立 | 只有一题对，说明它是靠别的线索蒙的 |
| **同一条对数** | 两题返回同一份文件的对数 | 越低说明越看年份；接近 8 说明年份完全没起作用 |

## 结果（`eval/reports/20261116-180137-time.md`）

| 口径 | 数字 |
|---|---|
| 单题 hit@1 | **7/16 = 44%**（23%–67%） |
| 成对通过 | **3/8 = 38%**（14%–69%） |
| 两题同一条 | **3/8** |

三对完全正确：阶段性降费率（2020 / 2024）、劳动能力鉴定办法（2022 / 2026）、
工程建设项目工伤保险（2020 / 2026）。

## 三种失败，性质完全不同

**1. 年份生效了但被闸门挡住（4 对）**
P02 精减退职、P04 灵活就业登记、P05 城乡居民养老衔接、P07 轻微违法清单——
两题都返回**拒答**。原因不是没找到，是"首条条款只覆盖 33%–46% 的提问词"。
这些题题干长、文件短，覆盖率闸门（0.5）按旧题调出来的，在这里误伤。

**2. 日期未知的文件抢位（1 对）**
P06 问 2019 年工伤辅助器具，返回 `沪人社福发〔2014〕45号`（有效期末尾没写）。
现在的规则是"日期未知 → 不筛掉、但排在有日期证明的后面"，它仍然赢了，
说明它的 BM25 分高到能压过一层分层差异。

**3. 真的对了（3 对）**
说明"年份过滤 + 分层"这套是有效的，只是还没覆盖全部情况。

## 这一轮改了什么

1. **从加权改成过滤**：原来给"该年有效"乘 1.2、无效乘 0.8，实测**完全没动排名**
   （同主题跨年文件正文几乎逐字相同，BM25 分差远大于 20%）。改成"明确不在该年有效期的直接不进候选"。
2. **加一层分层**：带年份时，先按"能否证明那一年有效"分层，再按分数排。
   日期未知的算低等级——**不知道 ≠ 有效**，但也不等于无效，所以不筛掉。
3. 单题 hit@1 从 **29% → 44%**，成对通过从 **14% → 38%**，两题同一条从 **7/7 → 3/8**。
4. dev 基线 55% 不变（dev 题不带年份），说明这条改动没有副作用。

## 已知边界（照实写）

- 只到年，不到月：2019 年 3 月和 2019 年 11 月当成一回事。
- 覆盖率闸门现在是最主要的瓶颈，但**没有在这套题上调**——这套题是新的，调它就是拿答案改卷子。
  要调只能在 dev 上找到同类长题干误拒，改完再回来验。
- 8 对样本太小：38% 的 95% 区间是 14%–69%，只能说"初步可用"，不能说"稳"。

## 面试怎么讲

> 我们没有直接说"支持时间感知"，而是造了 8 对答案会翻转的题：
> 同一个问题，问 2019 年和 2024 年，正确的文件不同。
> 结果 3/8 成对通过——比不做好，但远没到能用。
> 失败原因有两类：四对是被覆盖率闸门误拒（题长文件短），一对是日期未知的旧文件抢位。
> 这个数字不好看，但它比"支持时间感知"这句话有用得多。

## 附：能不能用"成文日期"补有效期

能，但只能当**下界**，不能当上界。

### 为什么下界是安全的

文件不可能在自己成文之前生效。所以 `effective_from` 缺失时，用成文日期兜底，
只会把"那一年不可能有效"的文件排除掉，不会凭空让谁变成有效。

实测：574 份里 **235 份缺生效日**，其中 **142 份有成文日期**可以借。

### 为什么上界不能推

很容易想到"规范性文件有效期 5 年"，但实测撑不住：

| 有效止日 − 成文日期 | 份数 |
|---|---|
| 0.5 年 | 44 |
| 1 年 | 49 |
| 2 年 | 29 |
| 4.5 年 | 12 |
| **5 年** | **115** |
| 其他 | 92 |

5 年只占 34%。剩下那些是"年度性通知"（一年一发的补贴、一次性节日补助），
按 5 年推会把它们判成"还活着"，比不推更糟。

所以上界只能来自**语料里明确写着的**：`有效期至 X`，或者关系层里的废止日。
两者都没有，就老老实实标未知。

### 效果

| 口径 | 补之前 | 补之后 |
|---|---|---|
| 时间类单题 hit@1 | 44% | 44% |
| 时间类成对通过 | 38% | 38% |
| dev hit@1 | 55% | 55% |

**没有变好。** 因为抢位的那些旧文件（2013、2014 年）成文日期都比提问年份早，
下界对它们不起作用——它们缺的是**上界**。

这条改动仍然留着，因为它修的是另一类错：问 2015 年的事，2020 年才发的文件不该出现。
这类题现在题集里还没有，属于"先修对，再等题"。

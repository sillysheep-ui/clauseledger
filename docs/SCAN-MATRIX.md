# 城市站点矩阵：该监督谁、谁抓得到、抓不到怎么办

> 结论先行：**没有任何一个城市的站点集合是"全"的**。所以我们不定义"全"，只定义**最低充分集**（minimum sufficient set），并把未覆盖的部分明写出来。

---

## 1. 每座城市应该监督哪些站

按"这件事归谁管"拆，七类构成最低充分集：

| 类 | 管什么 | 典型锚文本 |
|---|---|---|
| **P 门户** | 政府规范性文件总库 | 政策文件、政府信息公开 |
| **人社** | 落户积分、社保、补贴、职称 | 人力资源和社会保障局 |
| **教育** | 应届生资格、学历、三方协议 | 教育委员会 / 教育局 |
| **公安** | 户籍迁移、居住证 | 公安局（人口管理） |
| **住建** | 租房补贴、公租房、购房资格 | 住房和城乡建设 / 房屋管理局 |
| **医保** | 参保、报销 | 医疗保障局 |
| **公积金** | 缴存、贷款 | 公积金管理中心 |

**不是七类都要**：某类事项只有某类站发，覆盖矩阵按"城市 × 事项"填，不按"城市 × 七站"填。

## 3. 三种失败，三种 Plan B

### 失败 A：入口找不到（·）

不是"没有这个站"，是**门户首页不给直达链接**。杭州第一次扫描 0 命中，加了"部门导航页"这一跳后变成 6/6。

| Plan B | 做法 | 成本 |
|---|---|---|
| B1 | 门户 → 「部门/机构职能」导航页 → 部门站（两跳） | 已在做 |
| B2 | 站内搜索 + 站点地图 | 低 |
| B3 | **人工确认一次并固化**（30–60 分钟/城） | 中，**推荐** |

**最可靠的是 B3**：入口发现是**一次性的**，监测是**长期自动的**。花一小时人工确认清单，比每天猜更省。

### 失败 B：抓到了 404 / 页面搬走（✗）

长沙六类全 404——导航页里的链接是旧的。

| Plan B | 做法 |
|---|---|
| B4 | 从门户重新 discovery，找新路径 |
| B5 | 走省级站转载（长沙 → 湖南省政府/湖南人社） |
| B6 | 政府公报（法定公布载体，通常独立于门户） |
| B7 | 人工转录，标 `retrieved_via='transcribed'` |

### 失败 C：技术拦截

| 症状 | 原因 | Plan B |
|---|---|---|
| 412 + 完整浏览器头仍 412 | WAF 挑战（成都） | 无头浏览器带真实上下文；仍不行则转录 |
| `SSL: BAD_ECPOINT` | 国密 TLS（推断 SM2，深圳） | 换国密客户端（Tongsuo/gmssl）；成本高，**建议放弃该城** |
| 200 但正文 <100 字 | SPA 壳（一网通办、浙江政务服务网） | Playwright 渲染后取 `innerText` |
| 302 到登录页 | 登录墙（BOSS、ncss 职位接口） | 只抓公开部分，**不碰需登录数据** |

## 4. 这个矩阵的三个已知缺陷

诚实记录，防止把噪音当结论：

1. **错配**：北京"教育"被判 ✓，实际指向民族宗教事务委员会的一个页面（985 字）。锚文本含"教育"≠ 是教委站。
2. **低估**：长沙不是"没有"，是导航页链接全 404；郑州、济南的 · 也可能只是入口藏在别处。
3. **只测了"能不能打开"，没测"有没有政策文件"**。真正的判据是"该站有没有带文号的规范性文件列表"。

所以矩阵的用途是**缩小人工范围**，不是**替代人工确认**。

---

## 5. 结论：入口靠人，监测靠机器

- **一次性人工**：每城确认 5–7 个入口 URL，写进 `CityPack.sources`（半天/城，可外包给自己）
- **长期自动**：入口固化后，每天抓列表页 diff（`tools/watch/watch.py` 已验证：上海人社规文件 29 页 565 条 / 34 秒）
- **失败降级**：A/B/C 三类各自的 Plan B 写进城市记分卡，不隐藏

首批建议：**上海、杭州、西安、苏州、贵阳、武汉**（六城全绿），北京与广州做 L1 检索（缺人社直连），长沙/厦门/深圳暂缓并记录原因。

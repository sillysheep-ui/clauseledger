# 答案级评测：卡里有没有官方答案的关键事实

> `hit@1` 测的是"排序对不对"，产品给的是一张卡。
> 一张卡可以排错名次却仍然答对（三条候选里有一条够用），
> 也可以排对名次却答不全（关键数字在引文之外）。
> 这个评测补的就是这一层。

## 一、口径

**关键事实** = 官方答案里的"数字 + 单位"（元/万元/%/个月/日/个工作日/岁/分/倍/人）。
先把完整日期（`2024年1月1日`、`1月1日`）删掉，否则"1月""1日"会被当成金额类事实。

**覆盖** = 卡里能逐字找到的"数字+单位"占比。机械判定，不打主观分。

**样本** = 从 845 组官方问答里取"官方答案含数字事实、且金标文件对上"的题，共 **32 条**。

三条命令：

```bash
python -m tools.eval_answer          # 只打印汇总
python -m tools.eval_answer --write  # 落 data/reports/answer-eval.md
```

## 二、结果

| 层 | 覆盖 | 含义 |
|---|---|---|
| **卡**（用户看到的） | **34.4%**（22/64） | 5 条引文、每条 ≤240 字 |
| **候选条款**（top-5） | **35.9%**（23/64） | 检索层拿到的 5 条条款里 |
| **金标文件全文** | **64.1%**（41/64） | 事实确实在那份文件里 |

其它数：作答 **29/32（91%）**、全对 **8**、部分对 **12**、全错 **20**、金标文件在候选里 **20/32**。

**三层的差就是"丢在哪一层"：**

- 卡 → 候选（21→15）：展示截断 + 只取 3 条；
- 候选 → 全文（41→21）：**条款级选错**——检索到了对的文件，没选对那一条；
- 全文之外（64−41=23）：指标盲区（见第四节）。

## 三、按回答类型选条款（已实现，2026-11-18）

**做法**（`app/retrieval/answertype.py` + `search.py::_answer_type_boost` / `_attach_related`）：

1. 先判问题要什么：`num`（多少/标准/比例/期限）、`date`、`list`、`procedure`；
2. 在**已经排进前 5 的文件内部**，给"含该类内容"的条款加分（数字+单位、日期、列举、办理动词），不改变"是哪个文件"；
3. 给第一名补 **2 条同文件条款**，按"类型加分 + 提问词重合"选，卡片展示为"一个答案 + 这个文件里相关的几句"。

**效果**（同一批 32 题、同一套检索）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 卡里的关键事实 | 23.4%（15/64） | **34.4%（22/64）** |
| 候选条款里 | 32.8%（21/64） | **35.9%（23/64）** |
| dev hit@1（92 题） | 59%（48–68） | **60%（50–69）** |
| 卡 / 候选 的差距 | 15 vs 21（差 6） | 22 vs 23（**差 1**） |

**涨在哪**：前 5 名文件的条款里，按类型再挑 2 条补进卡片，卡与候选的差距从 6 个收敛到 1 个——
展示层基本不再丢事实。剩下的 12 个缺口（64−23 再加候选外的）属于**候选池没有条款**，见第四节。

**为什么只涨到这里**：类型加分只能重排"已经检索到的条款"。数字那条如果压根没进候选池
（问"标准是多少"，条文只写"320 元"，一个提问词都不含），加分也够不到它。
把上限放开到"该文件全部条款"再选，离线测到 16/64 → 21/64，但卡只多 2 个——剩下的是**选文件错**（见第四节）。

**没做的**：中文数字（"六十五周岁"）没有归一到 `65`；`num` 只认阿拉伯数字，会漏。

## 四、为什么候选层会掉这么多（已实测过的四种修法）

数字所在的条款往往**不含提问词**：问"缴费金额怎么确定"，答案那一条可能只有金额和公式，
没有"缴费金额"四个字。BM25 排不上它。

试过、**没有收益**的：

| 尝试 | 结果 |
|---|---|
| 主文件里再补 2 条相关条款（按提问词重合度选） | 卡覆盖 **23.4% → 23.4%（0pp）** |
| 主答案 + 父条款一起给 | 事实覆盖 14 → **16**（+2/64） |
| 主答案 + 该文件前 10 条条款 | 事实覆盖 14 → **21**（但等于把文件倒出来，不是"一个答案"） |
| 引文长度 240 → 400、条数 3 → 6 | **0pp** |

结论：**不是截断问题，是"该选哪一条"的问题。** 补条款、加长度都救不了。

## 四、指标盲区（必须一起说）

23 个"不在金标文件里"的事实，逐类看过：

1. **包装型文件**：如 `沪人社规〔2019〕23号` 全文只有 411 字 / 3 条，正文是"现对《…办法》作如下调整"——
   数字其实在**被引用的那份办法**里，不在这个通知里。金标指向通知，事实在别处。
2. **中文数字**：官方答案写"六十五周岁"，文件写"65 周岁"（或反过来）→ 字符串匹配失败。
3. **金标本身可能错**：v3 的金标是"标题相似 + 年份一致"匹配出来的，不是人工核对的。

所以 23.4% 是**下界**，但也没有高到可以当成绩。真实水平在 23%–35% 之间，无法更精确。

## 五、这个评测能证明什么、不能证明什么

**能**：说明"用户看到的卡里，官方答案的关键数字出现了多少"；说明瓶颈在条款选择而不是检索或截断。

**不能**：不能说明答案对不对（数字对了，条件可能反了——"不超过"写成"不低于"）；
不能覆盖非数字型答案（"需要哪些材料"这类问题没有数字）；
不能替代人工核对的引用支撑率（当前 @1 是 20%，见 `docs/EXPERIMENT-C.md`）。

## 六、下一步（按证据排序）

1. **按问题类型选条款**（不是按词重合）：问"多少/几/比例/期限"时，优先选含数字+单位的那条。
   这是唯一直接命中 41→21 这个缺口的方向。
2. **包装型文件识别**：正文出现"现对《…》作如下调整/补充"时，把被引用文件也拉进候选（当前 `relations` 只抽废止/延期，没抽"引用"）。
3. **中文数字归一**：`六十五` ↔ `65`，写一个转换器，同时用于抽取与匹配。
4. 人工核对 20 条，确认 23.4% 里有多少是"真缺"、多少是"指标误判"。

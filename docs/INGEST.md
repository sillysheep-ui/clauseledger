# 采集与数据规范

> 一句话：**宁可拿到少而准的，不可拿到多而脏的。降级可以，编造不行。**

本文回答七个问题：从哪取、哪些有价值、怎么更新、有哪些手段、拿不到怎么办、没有 PDF 怎么办、怎么保证准确。

---

## 1. 源分五级，只有两级能当证据

| 级 | 渠道 | 能当证据吗 | 例子 |
|---|---|---|---|
| **A 法源** | 政府门户政策库、部门「政策文件」栏目 | **能** | `rsj.sh.gov.cn/tzcwj_17653/` |
| **B 主管部门** | 人社局/教委/住建局 | **能**（更细） | `edu.sh.gov.cn` |
| **C 解读** | 政策解读、新闻发布会、12333 问答 | 只能作旁证/金标 | `tzcjd_17351/` |
| **D 办事指南** | 一网通办、政务服务网 | 不能，只做交叉验证 | 上海一网通办（76 B） |
| **E 聚合中介** | 落户计算器、公众号转载 | **一律不采信** | 各类「积分计算器」 |

**每条条款入库时必须记 `source_tier`（A/B/C/D）与 `retrieved_via`（见第 2 节）**，答案里可以据此决定要不要提示「此结论来自解读文件」。

---

## 2. 采集阶梯：拿不到就降一级，不跳级

| 级 | 手段 | 适用 | 可信度 | 自动化 |
|---|---|---|---|---|
| **L0** | 官方 JSON 接口 | 极少数城市有 | 高 | 全自动 |
| **L1** | 列表页 + 详情页 HTML | **主路径** | 高 | 全自动 |
| **L2** | 附件解析（PDF/DOCX/XLSX） | **规则主体常在这** | 高 | 全自动 |
| **L3** | 无头浏览器渲染后取 DOM 文本 | SPA 壳站（一网通办类） | 中 | 全自动 |
| **L4** | 人工转录（复制粘贴进文件） | WAF/412/登录墙 | 中 | **需人** |
| **L5** | 截图 + 人工确认 | 最后手段，仅存证 | 低 | **需人** |

两条硬规矩：

1. **L3 优先于 L4**。能用 Playwright 拿到渲染后的文本，就不要让人去复制——文本可校验，截图不可校验。
2. **L4/L5 的产物必须打标**。`retrieved_via='transcribed'` 或 `'attested_screenshot'` 的证据，在答案里显式标注，且该条款不能单独支撑 `satisfied` 判定（最多到 `unknown`），除非有第二来源。

## 3. 哪些文件有价值（四条判据，满足 ≥2 才收）

1. **是规范性文件**：正文或文首有文号（`X府发〔2026〕N号`、`X人社规〔2026〕N号`）
2. **含可判定条件**：数字阈值、期限、学历/户籍/社保年限限定
3. **有明确适用期**：写明施行日期，且未被废止
4. **有适用范围**：地域 + 人群 + 时间三要素至少两个

**直接丢弃**：新闻稿、领导讲话、会议纪要、纯流程指引（无任何门槛）、转载页（只保留原始 URL 做别名）。

**保留但降级**：政策解读、问答体（C 级，只做金标来源与交叉验证）。

---

## 4. 怎么"找到"而不是"猜域名"

猜 `www.<拼音>.gov.cn` 会漏（福州、青岛就这么漏的）。按这个顺序发现：

1. **省级门户 → 地市链接**：省级政府站的地市导航最可靠
2. **站内栏目遍历**：找到 `政策文件` 栏目后按分页往前翻（默认 3 年）
3. **sitemap.xml / RSS**：有就直接用
4. **站内搜索**：可用则用，但**不采信官方聚合搜索 API**（`sousuo.www.gov.cn` 实测 `totalCount=0`）
5. **上级转载**：市级站挂了，省级站常有转载
6. **搜索引擎只用来发现入口**，找到后必须回到原始站抓正文

---

## 5. 怎么实时更新

政策是**低频**变更（月级），不需要实时推送，需要的是**不漏**。

| 频率 | 动作 | 成本 |
|---|---|---|
| 每日 | 扫各城列表页首屏（HEAD + 首屏 diff） | 低 |
| 每周 | 扫详情页 sha256，抓新增/修订 | 中 |
| 每月 | 全量重解析（parser_version 变更时触发） | 高 |

**变更信号**四种：新文号出现 / 同标题出现新版本 / 「废止」公告 / 有效期到期。

每次变更产出一条 `ChangeEvent(action=added|revised|repealed|expired)`，`corpus_version` 递增；引用该条款的金标自动标记「需复核」。

**不要**做定时全站重爬——既慢又容易被封，列表 diff 足够。

## 6. 准确率怎么保证：四层校验

| 层 | 校验 | 失败处理 |
|---|---|---|
| **传输** | HTTP 200 + `Content-Length` 匹配 + sha256 + 编码嗅探（GB18030/UTF-8） | 重试 2 次，仍失败入 `failed_urls` |
| **文本** | 文号锚点存在 + 首尾完整性 + 抽取字数/页数比合理 | 标记 `TRUNCATED`，不截断入库 |
| **结构** | 条款编号连续性（一、二、三 不跳号）+ 条款数达阈值 | 标记 `PARSE_SUSPECT`，进人工队列 |
| **语义** | 数值必须绑谓词（「72 分」vs「10272 专业代码」）+ 引用回查 + 与解读文件交叉 | 冲突则进 `conflicts`，不自动裁决 |

**抽检制度**：每城每批随机 5% 人工核对原文，错误率 >2% 该城降级，>5% 停用。

**可测指标**（进 M0 记分卡）：附件发现率、条款切分准确率（人工标 20 份算 P/R）、字段抽取 F1（文号/成文日期/发文机关）、数值抽取准确率、转录错误率。

## 7. 拿不到时：截图与转录怎么用

**截图不是证据，是存证。** 机器无法校验像素里的数字，除非 OCR 后再人工校对——那成本比转录还高。

所以：

- **能渲染就拿文本**（L3），Playwright 拿 `innerText` 比截图强一个数量级
- **渲染也拦** → 人把正文复制进 `data/manual/<city>/<doc_no>.txt`，同时填 `provenance.json`（URL、抓取人、时间、原文页数、是否逐字）
- **截图只用于**：① 证明"我们确实去看过" ② OCR 兜底 ③ 争议时人工核对

**转录的三条约束**：逐字照抄不许总结；必须附 URL 与时间；抽查发现改字则该城全部转录作废。

---

## 8. 失败怎么记账

不删、不改、不隐藏。失败也是数据：

- `ingest_runs` 记录每次尝试（状态、HTTP 码、耗时、错误类型）
- 城市记分卡上明写「成都 412 反爬」「深圳 TLS 不兼容」
- README 的覆盖表里，未覆盖城市**列出来**，标原因

## 9. 我现在能做的 / 需要你做的

| 事 | 我做 | 你做 |
|---|---|---|
| 常规抓取 + 解析 + 校验 | ✅ | |
| Playwright 渲染 SPA | ✅ | |
| 过验证码 / 登录墙 | ❌ | ✅（或放弃该城） |
| 转录无 PDF 的页面 | ❌（不能操作你的浏览器） | ✅ 复制进文件 |
| 截图存证 | 脚本可截 | 判断截得对不对 |
| 5% 抽检 | 出对照页 | ✅ 判定对错 |

**没有 PDF 怎么办**：三种情况分开处理——①有 HTML 正文 → 直接抓；②只有扫描件 PDF → OCR + 人工校对；③连 PDF 都没有（内容在网页表格里）→ 转录或截图，标 L4/L5。

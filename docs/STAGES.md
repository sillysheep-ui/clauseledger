# 按阶段梳理：每步做什么、例子、怎么验、缺什么

> 数据规模：**574 份文件 / 131.4 万字 / 10,237 条条款**（索引 6,075 条叶子条款）。
> 每节固定四段：**做什么 → 例子 → 怎么验证 → 核验不足**。

---

## S1 获取：把字节拿回来

**做什么**：列表页 → 详情页 → 附件，落 `data/raw/<sha前12>/`，记 URL、抓取时间、哈希。

**例子**
- 列表页 `https://rsj.sh.gov.cn/tgwgfx_17726/index.html` 一页 20 行，自动翻 29 页 → **565 条**，34 秒
- 详情页 `.../tldgx_17731/20200617/t0035_1390708.html` → 16,643 B → `sha256=707f7a15…`
- 全量：**876 个文件 / 296 MB**（574 页面 + 296 附件 + 6 孤儿）

**怎么验证**
- 哈希可重算：同 URL 两次抓取若字节相同 → 哈希相同
- 孤儿扫描 `tools/ingest/orphans.py`：盘上有、记录里没有 → 6 个 / 246,641 B
- 覆盖率：337 城可达 313（93%）

**核验不足**
1. **6 个孤儿就是 6 次没被追的抓取**，没有自动告警，只能人工发现
2. **45 个 `probably_exists`（缺号）没有任何一份能确认"曾经存在"**，只能标"我们不认为它存在"
3. 抓取失败只写 `data/manifests/*.jsonl`（gitignore），**没有进证据链**——403 的文件在系统里等于不存在
4. 24 个 blocked 城市（成都、兰州已恢复，剩台州/郴州/湘西等）只是记录，没有复核机制

---

## S2 解析：字节变成文本块

**做什么**：HTML 选容器、PDF 逐页、DOCX 取段落；扫描件走 OCR；`.doc` 走 `textutil`。

**例子**
- 上海人社详情页正文在 `<div id="ivs_content">` 里，不在 `<p>` 里 → 早期这份只抽到 125 字；修好后 **342 字 / 13 块**
- 教委 13 号 PDF 52 页 → 1,344 块 / 34,238 字；`blocks[0]` 就是版头「上 海 市 教 育 委 员 会」
- 扫描件：`沪人社规〔2021〕29号` 原生 0 字 → OCR 救回 **10,241 字 / 90 条**

**怎么验证**
- 抽取路径统计：`native 134 / ocr 103 / textutil 59 / unsupported 0`
- 选择器护栏：命中容器若小于"最大文字块"的 70% → 退回最大块
- 单测：选择器、导航去重、`own_text()` 父子去重

**核验不足**
1. **没有"抽取完整度"指标**——不知道每份文件漏了多少字。唯一的手工对照是抽 20 份看，**没做过**
2. **表格型 38 份正文几乎不可用**：单元格被拆成 `序号`/`文件名称`/`文号` 碎片块
3. **`.docx` 表格文字全部丢失**（`python-docx` 只读段落），`沪人社规〔2022〕20号` 两个附件 0 字
4. 选择器护栏是启发式，**没有回归集**，改一次只能靠抽检

---

## S3 抽取：块变成字段

**做什么**：抽文号、标题、机关、四个日期。

**例子**
- `沪人社仲发〔2014〕38号`：文号来自列表页；落款「上海市人力资源和社会保障局 2014年9月1日」→ `sign_inline` → `2014-09-01`；列表页那行日期是空的 → `published_at=null`
- `沪教委学〔2026〕13号`：PDF 第 4 页同时有「2026年4月22日」（落款）与「2026年4月27日印发」→ 取 22 日，27 日被排除
- `沪人社规〔2019〕30号`：正文有 `自2007年1月1日起`，宽松规则会误取 → 已砍掉那条规则

**怎么验证**
- 11 条单测（独立块/同块/印发排除/无落款/施行/有效期/长期/空格日期/冲突/边界/unknown）
- 覆盖率：`doc_no` 100%、`title` 100%、`issued_at` 78%、`published_at` 51%、`effective_to` 63%
- 冲突清单：22 份落款与列表日期不一致，全部带 URL 供人工核对

**核验不足**
1. **22 份冲突没有裁决**——我只标了"不一致"，没有判断谁对
2. **`issued_at` 的 78% 里没有一个经过人工确认**，正确率未知
3. **`agency` 覆盖率 0%**：机关名没抽，导致"谁发的"这个问题答不了
4. **`published_at` 51%**：详情页明明有「发布时间：2014-09-18」，没抽
5. 落款抽取只看末尾 24 块，**长附件文件（教委 13 号）直接漏掉**

---

## S4 结构化：块变成条款

**做什么**：按 7 级编号（`第X章/第X节/第X条/一、/（一）/1./（1）`）归组，保留页码与字符区间。

**例子**
- `沪教委学〔2026〕13号`：1,344 块 → **105 条条款**（`一、`29 / `（一）`12 / `1.`64）
- 父条款 `一、` 区间 `10318–12021`，子条款 `1.` 区间 `10335–10588`，**父含子全文**
- 引用可回到原文：`《沪教委学〔2026〕13号》一、/（一）/1.（第 21 页）`

**怎么验证**
- 单测：编号识别、父子区间、无编号兜底
- 条款总数 10,237；索引叶子 6,075；0 条款 55 份

**核验不足**
1. **条款切分正确率从未测过**——没有标注集，不知道切断了没有、切少了没有
2. **0 条款 55 份**（9.5%），其中 26 份无附件、38 份是表格/延期清单
3. **父子重复存储 2.54 倍**（32,895 字 vs 83,474 字），体积浪费
4. 同一文件两套编号（通知 + 附件《办法》）会混排

---

## S5 检索：问题找到条款

**做什么**：jieba + BM25，规则闸门（城市/领域/覆盖率），同族现行版本前移。

**例子**
- `硕士毕业落户能加多少分` → `score=6.40 cov=0.50` → `沪教委学〔2026〕13号` 一、/（一）/1. 第 21 页
- `北京落户需要几年社保` → `not_covered`（当前只接入上海）
- `老婆生孩子能休多久` → `out_of_domain`
- `老婆生孩子能休多久` 这类口语 → 拒答，**这是硬伤**（见不足 1）

**怎么验证**
- 203 条用例（official 168 / out_of_scope 30 / version 5），dev/test/holdout 60/25/15
- dev：**hit@1 54%（44–63%）、hit@3 62%、MRR 0.60、应答率 80%、已答中 68%**
- 泄漏度 36%；同族版本前移带来 +9 改好 / 0 改坏（p=0.0039）

**核验不足**
1. **paraphrase 一条都没有**——官方问答都是书面语，口语提问直接拒答
2. **泄漏 36%**：题目里的词逐字出现在条款里
3. **单金标**：一份政策可能被 2–3 个文件回答，只认一个答案
4. **test split 只有 50 条**，MDE 25pp——现在报的 54% 撑不起"改进 5pp"这种结论
5. **没有人工核验过任何一条检索结果**

---

## S6 判定：规则算出结论

**做什么**：把 PDF 里的评分办法**人工抄成 YAML**（37 项 / 248 分 / 3 个直落条件），代码按四态计算。

**例子**
- 硕士 + 一类校 + 成绩一等 + CET6 + 计算机 + 重点学科 = 24+15+8+8+7+7 = **71 分，差 1 分**
- 缺字段的项按组内最大值计入上限 → 输出区间（71 / 上限 89），不输出假精度

**怎么验证**
- 8 条单测（直落、71、+荣誉 81、全低、封顶 15、缺字段 unknown、页码、文号引用）
- 规则每项带 `page`，可回原文核对

**核验不足**
1. **规则是人工抄的，没有第二人复核**——抄错一个分值就全错
2. **71 分这个结论没有人验算过**
3. 附录 1/3/4 高校名单、附录 5 重点学科**未解析**（`meta.unresolved` 列着）
4. 单位资质、居转户、受理流程都没做

---

## S7 评测：把以上全部量出来

**做什么**：固定用例 + 冻结纪律 + 配对比较。

**例子**
- v1：50 条 → 发现 out_of_scope 拒答率只有 20%（12 条瞎答）
- v2：203 条 → dev hit@1 45% → 同族版本前移 → 54%
- 冻结：`eval/FROZEN.json` 记 sha256，test 不得调参

**核验不足**
1. **判分脚本没有单测**（`tools/eval_v2.py` 无测试）
2. **dev/test 同源**：题目都来自同一个官方问答栏目
3. **holdout 从未跑过**
4. **没有一次人工标注**——所有分数都是脚本自评

---

## S8 编排 / 门控 / 界面：**完全没做**

- 没有状态机（可恢复、幂等、审批）→ 项目主线里最重要的三件事都还只是设计
- 没有界面 → 所有能力只在命令行
- 没有多 agent → 只有 Advisor/Auditor 的设计

---

## 总的核验缺口（按严重度）

| 缺口 | 影响 |
|---|---|
| **全程没有人工标注/核对** | 所有"准确率"都是脚本自评，面试一问就露 |
| 条款切分正确率未测 | 引用可能指向错的位置 |
| 检索只有 50 条 test、无口语题 | 效果数字撑不起结论 |
| 判定规则无人复核 | 结论对错未知 |
| 编排/门控/界面未做 | 主线还没开始 |

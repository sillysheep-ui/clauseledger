# 一条记录经过哪几步，每步保留什么

> 上一版把三件事混在一起了：**处理阶段**、**存储层**、**字段来源渠道**。
> 这一版按阶段排：获取 → 解析 → 抽取 → 结构化。每个字段只属于一个阶段。

---

## 0. 主轴：四个阶段

```
获取 acquire      字节进来，只知道"这是一个 URL 的返回"
  ↓ 得到的只有：url / fetched_at / sha256 / http_status / retrieved_via
解析 parse        字节变成文本块，只知道"这段字在第几页"
  ↓ 得到：blocks[] / page_kind / extract / ocr_conf / attachments[]
抽取 extract      块变成字段，这时才知道"这是哪份文件、什么时候发的、什么时候失效"
  ↓ 得到：doc_no / title / agency / 四个日期 / 有效期
结构化 structure  块变成条款，变成能检索、能引用的单元
  ↓ 得到：clauses[] / index / 判定输入
```

一句话：**获取层不知道手里是什么文件；抽取层才知道。**

---

## 1. 逐阶段：输入 / 产物 / 失败模式

### 阶段一：获取（`tools/ingest/fetch.py`）

| 产物 | 含义 | 怎么来 |
|---|---|---|
| 字节文件 | 原件 | HTTP GET，落 `data/raw/<sha前12>/<原名>` |
| `url` | 从哪拿的 | 列表页链接 / 人工 fixture |
| `fetched_at` | 什么时候拿的 | 抓取时刻 |
| `page_sha256` | 拿到的到底是什么字节 | 对字节算哈希 |
| `retrieved_via` | 用什么方式拿的 | `crawl` / `manual:official` / `manual:mirror` |
| `http_status` / `error` / `attempts` | 没拿到的原因 | 失败时写进登记层 |

**这一层刻意不做的事**：不判断这是政策还是通知、不抽文号、不判效力、不去重、不决定版本。
**失败模式**：抓取失败被静默吞掉 → 系统里等于"不存在"（修法：四值 `doc_status`）。

### 阶段二：解析（`tools/ingest/parse.py`）

| 产物 | 含义 | 怎么来 |
|---|---|---|
| `blocks[]` | 文本块 `{i, kind, page, text}` | HTML 容器选择器 / PDF 逐页 / DOCX 段落 |
| `page_kind` | 载体 | `html` / `pdf` |
| `extract` | 抽取方式 | `native` / `ocr` / `textutil` / `unsupported` |
| `ocr_conf` | OCR 置信度 | 中位置信度 |
| `attachments[]` | 附件清单 | 详情页链接 + PDF 内嵌 |
| `parser_version` | 解析器版本 | 常量 |

**这一层刻意不做的事**：不知道文号、不知道日期、不切条款。
**失败模式**：程序不报错但内容为空（扫描件、`div` 正文、选择器截断、表格型 docx）。

### 阶段三：抽取（`tools/ingest/dates.py` + 文号标题规则）

| 产物 | 含义 | 来源通道 |
|---|---|---|
| `doc_no` + `doc_no_source` | 这是哪份文件 | ①列表页 ②人工 ③正文正则 |
| `title` | 标题 | ①列表页 ②`h1` ④PDF 版头 |
| `agency` | 发文机关 | ④版头 / 落款（**尚未实现**） |
| `issued_at` + `issued_at_source` | **成文日期**（落款） | ②正文落款 ①列表页 ③详情页发布时间 |
| `published_at` | **印发日期** | ①列表页「生成日期」 ③详情页「发布时间」 |
| `effective_from` | 施行日期 | ②正文「自 X 起施行」 |
| `effective_to` + `effective_to_source` | **有效期至** | ①列表页列 ②正文 ③`long_term` |
| `issued_year` / `date_precision` | 兜底与精度 | 文号里的年份 |

**这一层才产生"身份"和"时间"。**
**失败模式**：抽错比抽不到更危险 —— 例如把「有效期至 2028-03-31」当成成文日期。所以：抽不到写 `None` + `unknown`，冲突的两个日期都留。

### 阶段四：结构化（`tools/ingest/clause.py` + `app/retrieval/index.py`）

| 产物 | 含义 | 怎么来 |
|---|---|---|
| `clauses[]` | 按编号归组 `{path, label, level, text, page, start, end}` | `split_clauses()` |
| 索引行 | 检索单元 | 叶子条款 + 引用偏移 |
| `stats` | 块数/字数/条款数 | 计算 |

**失败模式**：无编号短通知切出 0 条 → 检索不可见（已用段落兜底）。

## 2. 存储层（与阶段正交）

| 层 | 位置 | 存的是哪个阶段的产物 | 能否重算 |
|---|---|---|---|
| 字节层 | `data/raw/` | 阶段一 | ❌ 不可再生 |
| 记录层 | `data/processed/` | 阶段二 + 三 | ✅ |
| 索引层 | `data/index/` | 阶段四 | ✅ |
| 登记层 | `data/registry/` | 阶段一的失败 + 阶段三的身份 | ✅ |

---

## 3. 明确不保留

| 不存 | 为什么 |
|---|---|
| 文件名 | 流水号 `t0035_1390708.html`，没有语义 |
| HTTP 响应头 | 只留状态码 |
| 页面截图 | 按需渲染（`tools/report/shots.py`），不入库 |
| 摘要 / 结论 / 答案 | 派生量，每次重算 |
| 按城市/时间分目录 | 目录一变引用就断 |

## 4. 当前覆盖率

| 字段 | 阶段 | 现在 | 目标 | 差距怎么补 |
|---|---|---:|---:|---|
| `url` / `sha256` / `fetched_at` | 一 | 100% | 100% | — |
| `blocks` / `page_kind` | 二 | 100% | 100% | — |
| `doc_no` / `title` | 三 | 100% | 100% | — |
| `issued_at`（天级） | 三 | **77%** | 90% | 落款 P1/P2 已用尽；剩余多是网页无落款的转发/短通知 |
| `published_at` | 三 | **99%** | 90% | 已达（补读 `<meta name="PubDate">` 后从 51% 跳上来） |
| `effective_to`（有值或显式 unknown） | 三 | 100% | 100% | 已达 |
| `agency` | 三 | **100%** | 90% | 已达（其中 163 份是文号前缀推断，见下） |
| `clauses` | 四 | 90% | 95% | 表格型文件 |

### 4.1 两个字段是怎么补上来的

- **`published_at` 51% → 99%**：真正的日期不在正文，而在页面的 `<meta name="PubDate" content="2022-06-14 12∶06">` 里。解析器四年（v0.1–v0.3.15）都没读过 `<meta>`，一直在正文里找"发布时间"——378 份 HTML 里只有 1 份正文含这四个字。补读 meta 后 `pubdate` 来源 345 份、`print`（版记印发）209 份、`list`（列表页）17 份，仍未知 3 份。
- **`agency` 0% → 100%**：四条通道按可靠性排序——标题前缀 199 份、版头块 160 份、落款 52 份、**文号前缀推断 163 份**。最后一条是推断不是抄录（`沪人社规…` → 上海市人力资源和社会保障局），所以 `agency_source` 一定写出来；联合发文若走这条通道只会得到主管部门，不是全部发文机关。
- **顺带修掉一条脏数据**：`沪劳资发〔87〕130号` 的 `issued_at` 曾被列表页"有效期至"列污染成 `2031-08-15`（未来日期）。回填时加一条硬规则——**成文日期不可能在未来**，命中的记录重新用落款抽取，抽不到就置 `unknown` 并写 `issued_at_note`。

## 5. 判断标准

一个字段该不该留，问三句：

1. 它能不能改变下游某个决定？（引用、过期判断、覆盖判断）
2. 它能不能重算？能重算的别存。
3. 它错了会不会安静地错下去？会的话必须配 `*_source` 和显式 `unknown`。

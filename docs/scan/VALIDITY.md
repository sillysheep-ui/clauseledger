# 有效期链：每一份文件自己的到期日

「这份文件现在还有效吗」是判定的第一步。政策文本里写着两个日期：**施行日**（自 X 日起施行）
和**有效期至**（规范性文件通常五年）。但还有第三种情况：文件自己写着 2020 年到期，
后面又来一份《关于延长部分行政规范性文件有效期的通知》把它延到 2022 年。

只读文件自身的「有效期至」会得出错误结论。这一层就是把这些延期通知接回被延长的文件上。

## 一、规则

代码在 `tools/ingest/validity.py`，一条命令把结果写回 `data/processed/*.json`：

```bash
python -m tools.ingest.validity --report   # 只看统计，不写回
python -m tools.ingest.validity --apply    # 写回 valid_until / extended_by / validity_source
```

判定一份文件是不是延期通知：标题同时含「延长」和「有效期」。共 27 份。

从通知里抽「文号 → 新到期日」的配对，分三种情况：

| 通知里的写法 | 处理 |
|---|---|
| 只出现一个日期（「…有效期延长至 2028 年 8 月 15 日」） | 该日期适用于正文点名的所有文件 |
| 多行、每行「文号 … 有效期至 X 年 X 月 X 日」 | 按行配对，每份文件拿自己那行 |
| 文号一列、日期一列（扫描件常见） | **整份放弃**，记未解析 |

第三种情况是踩出来的：列优先排版下，「文号1 文号2 日期1 日期2」按距离配对，
会把日期1 同时配给文号1 和文号2。宁可标「未解析」，也不能给一份文件安错到期日——
错的有效期会直接导致「已失效的文件被当成现行」这种最难发现的错误。

写回时另有一条：**自身到期日与延期日期取较晚者**，并把来源记成
`validity_source ∈ document（自身声明）| extension（延期通知）| unknown（都没有）`。

## 三、接入索引

`app/retrieval/index.py` 现在用 `valid_until or effective_to` 判状态，
`Clause.effective_to` 也带这个值，所以卡片上显示的「有效期至」是延长后的日期。
`docs_meta.json` 里同时留了 `own_effective_to` 与 `extended_by`，便于追溯「为什么它是有效的」。

文件级状态分布（条款级见 `data/index/stats.json`）：

| 状态 | 只看自身到期 | 接入延期链后 |
|---|---|---|
| 现行 | 123 | **129** |
| 已过期 | 239 | 257 |
| 未知 | 210 | **186** |
| 未生效 | 2 | 2 |

已过期从 239 涨到 257 是正常的：本来「没有到期信息」的文件里，有一批被延期通知
点名之后有了明确到期日，而那些日期已经过去——**未知变少、过期变多**，这正是补上
延期链想要的结果。

## 四、剩下的 3 份未解析

| 文号 | 原因 |
|---|---|
| `沪人社规〔2022〕35号` | 被延长的文件不在语料里 |
| `沪人社规〔2022〕37号` | 同上 |
| `沪人社规〔2023〕14号` | 同上 |

这三份是**单文件延期**：正文只写「《……办法》有效期延长至 X 年」，被延长的文件
本身不在 574 份语料里（多半是早年已废止、没抓到的文件）。这不是解析失败，
补录那份文件之后这条边自然就有了。

另外 5 份原先卡住的通知已经解决，靠三个改动：

1. **文号正则容忍空格**。表格里写的是「沪人社福发 〔 2014 〕 36 号」，
   原来的正则要求文号连写，导致 `沪人社规〔2019〕31号` 的 14 行整份配不出。
2. **列优先配对时剔除通知自身的文号**，并要求文号数与日期数**完全相等**才配。
   扫描件的版头里也有通知自己的文号，不剔掉数量永远差一个；数量不等就整份放弃
   ——少一个日期还按顺序硬配，会让第 3 个文件拿到第 4 个日期。
3. **扫描件用 Vision 的字级坐标重建表格**（`tools/ingest/vision.py`）。
   先试过两条路都不行：`ocrmac` 返回的 bbox 全是 `[0,1,1,0]`（不提供逐块坐标）；
   这几份是扫描件，`pypdfium2` 的文本层为空，拿不到字坐标。
   最后直接调 macOS `Vision.VNRecognizeTextRequest`，拿到每个文本块归一化的
   `boundingBox`，然后：按表头（序号 / 文件名称 / 文号 / 延长有效期）的 x 定列边界
   → 同一列里把折行碎片按 y 相邻拼回单元格（「沪人社福发」+「（2010）2号」）
   → 同一页内第 i 个文号配第 i 个日期，数量不等整页放弃。
   `沪人社规〔2021〕6号`（13 行）、`〔2021〕8号`（12 行）、`〔2021〕10号`（7 行）
   因此全部解析出来。

为什么不干脆人工录入：这 5 份里有 32 行配对，人工抄一遍要半小时且没有校验；
坐标法有「数量必须相等、同页内配对」两条硬约束，配错会立刻表现为数量不齐而放弃。

## 五、对评测的影响（A 口径）

A 口径是「以解读文章发布日为 `as_of`，判 RAG 当时能不能找到正确文件」。
预检 183 道官方题：122 当时有效 / 30 当时已过期 / 6 当时未生效 / 24 无日期 / 1 无施行日。

**接入延期链后这组数字没变**。原因在 `沪人社规〔2018〕46号`：它被 `沪人社规〔2020〕9号`
延到 2022-12-31，而引用它的解读文章发布于 2023-01-18，仍晚于到期日；
真正把它延到 2028 的那份通知尚未解析（在列优先的 8 份里）。
这说明「延期链」与「A 口径」是两件独立的事：前者把已知的边接上，后者还要逐题定 `as_of`。

## 六、边界

- 只处理「延长有效期」这一类通知。废止、部分条款修改、重新发布都还没有接入
  （`app/retrieval/search.py` 里另有一份手写的废止表，覆盖 19 对）。
- 目标文件不在语料里的通知会被记成「没认出被延长的文件」，不是解析失败。
- 列优先的扫描件已经用 Vision 坐标重建过一轮（见第四节），剩下 3 份是**目标文件不在语料**，
  不是解析失败，不再硬啃。

## 八、状态是投影：时间段，不是到期日

到 2026-11-24 之前，系统里存的是**一个** `valid_until`。它回答不了「2021 年 5 月那天它有效吗」：
文件可能 2020 年到期、2026 年才被一份新通知延到 2031 年，中间那几年是**断的**。
把有效期压成单值，等于默认"断档不存在"。

现在的分层：

| 层 | 位置 | 内容 | 谁写 |
|---|---|---|---|
| 文件自述 | `data/processed/*.json` | `effective_from` / `effective_to`（正文原话） | 解析器 |
| 延期关系 | `data/registry` 派生 → `data/derived/validity.json` | `edges`：谁把谁延到哪一天 | `tools.ingest.validity` |
| 有效期区间 | 同上 `periods` | `[{start, end, by, gap}]`，断档标 `gap: true` | 同上 `periods()` |
| 某天的状态 | 运行时算 | `effective / expired / not_yet / repealed / unknown` | `app/domain/validity.py::status_for` |

当前派生结果：**493 份文件有区间、90 条延期边、1 处断档**。

规则：
- 通知的生效日 ≤ 当前段的到期日 → 往后**延长当前段**；
- 晚于 → **新开一段**并标 `gap=true`，那段空档就是失效；
- 自身到期日永远只读 `effective_to`，不读派生值（否则上一轮的结果会被当证据）。

接线三处：
1. `app/retrieval/search.py::_rank_at`：按 `status_for(doc_no, as_of)` 分 3/1/0，断档年的文件不进候选；
2. `app/answer/cards.py::_validity_notes`：卡上「时效提醒」，只对 expired/repealed/not_yet
   （以及历史时点的 unknown）提示，未知不等于失效；
3. `tools/jobs/collect.py::derive`：每日采集后重算延期链并重建索引，`--no-derive` 可跳过。
   失败只打印一行、不阻断采集——检索继续用上一版索引。

为什么不做成字段：状态是**时间的函数**。同一份 `沪人社规〔2018〕46号`，
2021 年有效（被〔2020〕9号延到 2022-12-31），2023 年起过期。存成字段就只能在"写入那一刻"是对的。

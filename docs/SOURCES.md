# 信息渠道（SOURCES）

> 回答一个问题：**我们的条款证据从哪来，哪些地方不采信。**
> 全部状态为 2026-11-11 实测，不是推测。探测口径：1 req/s，普通 UA，跟随跳转。

---

## 1. 渠道分级

| 级 | 渠道 | 用途 | 能否当证据 |
|---|---|---|---|
| **A 法源** | 市政府门户政策库、部门「政策文件」栏目 | 条款原文、文号、成文/发布日期 | **能**，唯一可引用的层 |
| **B 主管部门** | 人社局、教委、住建、医保局等 | 规则主体常在这里（比门户更细） | **能** |
| **C 解读** | 「政策解读」栏目、新闻发布会实录、12333 问答 | 口径确认、金标来源 | 只能作**旁证/金标**，不作条款 |
| **D 办事指南** | 一网通办、政务服务网 | 材料清单、办理流程 | **不能**，只做交叉验证 |
| **E 聚合/中介** | 落户计算器、公众号转载、内容农场 | — | **一律不采信** |

判定理由：A/B 有文号与发布日期，能定位到"哪份文件、第几条"；C 是官方对文件的解释，可用于校准但本身不是规则；D 是流程性描述，随窗口口径变；E 无法追溯。

1. **办事大厅全是单页应用**（76 B、7 字、360 字），没有浏览器拿不到内容。所以 D 级渠道只能用于人工核对，不能进采集管线。

## 3. 一个可复用的结构（上海人社）

同一件事有三种载体，这正是 `ARCHITECTURE.md` 里说的"同一事项三种载体"：

| 栏目 | 路径 | 性质 |
|---|---|---|
| 政策文件 | `/tzcwj_17653/index.html` | **A 级，规则主体** |
| 政策解读 | `/tzcjd_17351/index.html` | C 级，Q&A 体 |
| 公示公告 | `/tgsgg_17341/index.html` | 时效性通知，含搬迁/关闭等噪声 |

上海 pilot 那份落户通知就是"公告 + 附件"的组合：公告壳在门户，规则主体在 `edu.sh.gov.cn` 的附件里。

## 4. 抓取纪律（写进代码，不靠自觉）

- `User-Agent` 表明身份与联系方式，不伪装成浏览器去绕反爬
- 1 req/s，失败指数退避，单站并发不超过 1
- 遵守 `robots.txt`：实测 `gov.cn` 为 `Allow: /1` + 若干 `Disallow`（含 `/2016zhengce/`），`/zhengce/` 未被禁
- 原始内容按 `sha256` 缓存到 `data/raw/`（不入库，可再生）
- 每份文档必存：`doc_no`（文号）、发文机关、成文日期、发布日期、有效性、来源 URL、抓取时间、`sha256`、附件关系
- **双日期**要分开存：上海那份是"印发 2026-04-27 / 发布 2026-05-06"，混成一个字段会在版本比对时出错

## 6. 对 M0 的影响

- **成都 412**：先当"不可采集"处理。除非找到不反爬的替代入口（如省级站转载），否则不进首批。
- **深圳 TLS**：技术上不是加个 UA 能解决。要么引入国密 TLS 客户端（成本高），要么用广东政务作旁证、深圳不进 L2。
- **杭州/北京/上海**：部门站可直接抓，具备 L2 前提。
- **结论**：五城预期是"3 城可做、1 城受阻、1 城技术不兼容"——这比"五城都行"更接近事实，也更能讲清取舍。

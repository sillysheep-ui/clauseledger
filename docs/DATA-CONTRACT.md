# 采集数据契约：看哪些站、每个站必须给什么

> 目的：把"数据够不够"从感觉变成清单。一个城市接不接，看它能不能满足本契约，而不是看它好不好看。

---

## 1. 按"事项"反推要看的文件，再反推站点

判定一件事能不能办，需要四类材料，缺一类就会出错：

| 材料类型 | 用途 | 通常在哪 |
|---|---|---|
| **规范性文件**（正文） | 规则来源、文号、有效期 | 门户政策库 / 部门「政策文件」 |
| **附件**（PDF/DOCX/XLSX） | **阈值、积分表、目录**常在这里 | 详情页附件区 |
| **实施细则 / 操作口径** | 把"原则上"变成可判定 | 部门「其他文件」「解读」 |
| **办事指南** | 材料清单、办理流程 | 一网通办 / 政务服务网 |

上海实测印证：门户页 17 KB 正文 0 表格无「72」，**规则主体在附件，附件在教委站**。

所以"要看的网站" = 能发这四类材料的站，共七类（见 `SCAN-MATRIX.md` §1）。

## 2. 每个站必须提供的字段（契约核心）

| # | 字段 | 必填 | 为什么 | 缺失后果 |
|---|---|---|---|---|
| 1 | 标题 | ✅ | 人工检索、去重 | 无法建索引 |
| 2 | **文号** | ✅ | **唯一键**，标题会改文号不会 | 版本比对失效 |
| 3 | 发文机关 | ✅ | 判断权威性与管辖 | 无法判适用 |
| 4 | **成文日期** | ✅ | 判定时的 `as_of` 基准 | 时序错乱 |
| 5 | 发布日期 | ✅ | 与成文日期不同（上海实测：印发 04-27 / 发布 05-06） | 生效时间判错 |
| 6 | **有效性 / 有效期至** | 强推荐 | 自动判废止 | 引用失效条款 |
| 7 | 正文（HTML 或 PDF） | ✅ | 条款切分 | 无内容 |
| 8 | 附件 | 条件必填 | 规则主体常在附件 | 漏掉阈值 |
| 9 | 事项类别 | 我们打标 | 路由到 CityPack 事项 | 检索不到 |
| 10 | 适用地区 | 站点推断 | 防止跨城混答 | 地域混淆 |
| 11 | **原文 URL + 抓取时间 + sha256** | ✅ | 证据链与版本 | 不可审计 |

上海人社「规文件」栏目**天然满足 1–7 与 11**（表格列就是标题/文号/生成日期/有效期至），属高质量源。

## 3. CityPack：每城一份 YAML，人工确认一次，机器长期跑

结构见 `citypacks/sh.yaml`。一个 source 只需填九项：

```yaml
- id: sh-rsj-guifan          # 唯一
  kind: policy_list          # policy_list | policy_detail | guide | notice
  tier: A                    # A 法源 / B 主管部门 / C 解读 / D 指南
  dept: 人社
  url: https://.../index.html
  pagination: {style: index_n}   # index_n | query_param | none
  table: {cols: [title, doc_no, issued_at, valid_until]}
  attachments: {selector: "a[href$='.pdf']"}
  covers: [落户, 社保, 补贴]
  status: verified           # verified | unverified | blocked
```

## 5. 需要你拍板的三件事

1. **首批城市**：六城全绿，还是收缩到三城（上海/杭州/西安）做深？
2. **事项优先级**：落户积分 / 租房补贴 / 应届生身份 / 社保年限 / 职称认定——先做哪两个？
3. **降级底线**：允许人工转录（L4）作为补充通道吗？还是"抓不到就不覆盖"？

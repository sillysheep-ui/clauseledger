# AUDIT.md — 五轮审核记录

> 审核对象：`DESIGN.md`（v1 方案）、`FRAMEWORK.md`（v1 骨架）、`REVIEW.md`（第 0 轮自审）。
> 每一轮换一个视角，独立找问题。**第 5 轮结束时，剩下的都是"已接受的取舍"，不是"没看见的坑"。**

---

## 第 1 轮：这个项目值得做吗（价值视角）

**方法**：先找"已经有人在解决"的证据，再问我们凭什么比它好。

**发现 1：算分这件事已经商品化了。**
搜索"上海应届生 72 分"返回的前 8 个结果**全是落户中介站的在线计算器**（[vgxf](https://www.vgxf.com/shangxue/6870.html)、[tltzg](https://www.tltzg.com/luohu/10584.html)、[hukou021](https://m.hukou021.com/html/yingjiesheng/redian/22806.html) 等）。如果项目卖点是"帮你算 72 分"，第一轮就该毙掉。

**发现 2：真正的规则不在公告正文里。**
实测抓取[上海市教委 2026 年通知](https://www.shanghai.gov.cn/gwk/search/content/f4df3bb5b82747b893b1eb10ca2b1f8b)：正文 17KB、38 行、**0 张表格、全文不出现"72"**，最后一行写着"附件请至'上海教育'网站下载"。
也就是说：**用户读到的公告是壳，能用的规则在附件里，而附件在另一个域名**。中介站做的其实就一件事——替你把附件嚼碎了。

**发现 3：差异化只剩一个位置。**
中介站的输出是"你有希望/包过"，官方的输出是"全文自己看"。中间缺的是：**给我一句能核对的结论，并且告诉我这句话出自哪份文件哪一条**。

**结论**：价值成立，但**必须换卖点**——不是"算得准"，是"说得清、可核对、不知道就说不知道"。
**修法**：README 首屏删掉"帮你算分"，改成"每条结论点得回原文；判不了就告诉你缺什么"。这恰好和最初定的"审计优先"是同一条线。

## 第 2 轮：数据到底长什么样（领域视角）

**方法**：不看搜索结果摘要，直接抓原始页面，量正文、表格、附件、字号、日期。

**实测记录（2026-11-11）**

| 站点 | 结果 | 含义 |
|---|---|---|
| shanghai.gov.cn 政策详情页 | 200，17KB，38 行正文，0 表格 | 正文是条文骨架，规则在附件 |
| 附件域 edu.sh.gov.cn | 200，66KB 首页 | 可达，但要跨域追 |
| firstjob.shec.edu.cn | 200 但只有 **464 字节** | JS 壳，抓不到内容 |
| gov.cn `/zhengce/zhengceku/` | **403** | 部分栏目直接封 |
| shanghai.gov.cn 栏目列表页 | 0 个 .pdf 链接 | PDF 只在详情页挂 |
| 文号 | `沪教委学〔2026〕13号` | 身份键可用 |
| 日期 | 印发 2026-04-27 / 发布 2026-05-06 | 双日期，必须分开存 |
| 同名文件 | 2024 版、2026 版都在 | 版本对比是真需求 |

**发现 4：附件追踪必须是一等公民，不是"顺便下一下"。**
抓完正文就收工，会得到一堆"原则上…"的空壳，规则一条都抽不出来。

**发现 5：覆盖率声明必须包含附件维度。**
"已抓 450 份文件"不等于"450 份都可解析"。要分开报：正文成功率、附件发现数、附件下载成功率、附件可解析率。四个数字任何一个不达标，拒答理由要能指出来。

**发现 6：2024 vs 2026 是一个天然的演示素材。**
同一个问题，两版答案不同（材料清单、分数要求、办理流程）。这是"版本管理"唯一能让人当场看懂的方式，比讲 schema 有用十倍。

**结论**：范围必须重排——**先做"一份文件的完整链条（含附件）"，而不是"三城六事项的广度"**。
**修法**：M0 闸门改为"拿 2024 和 2026 两版完整跑通，量附件成功率"，不通过就改范围。

## 第 3 轮：技术上站得住吗（正确性视角）

**方法**：逐个环节问"这句话在实现层面对应什么代码"，写不出来的就是空的。

**发现 7（重要）：三态不够，必须四态。**
"你不符合条件"和"这条政策不针对你"是两件事。用户是硕士、政策只招博士——不是"不符合"，是"不适用"。混在一起，混淆矩阵会失真，答案也会说错话。
→ 判决改为 `satisfied / unsatisfied / unknown / not_applicable`，另有语料层的 `no_policy`。

**发现 8（重要）：检索的职责被高估了。**
v1 把检索写成"混合召回 top-20"，但真正的工作是两件不同的事：
- **路由**：这段问题该看哪几个文件（语义检索在这里有用）
- **举证**：规则指向哪几条条款，直接按 id 取原文（**不需要检索**）

把两者混成一次 top-k 检索，会导致"结论靠相似度"，正好踩中本项目要避免的那条线。
→ 拆成 `route_policy`（文件级）和 `bind_rules`（条款级，规则驱动）。

**发现 9：中文词法检索在 Postgres 里不存在。**
`pgvector/pgvector` 镜像不带中文分词，默认配置把整句当一个 token。v1 说的"BM25 那一路"是空的。
→ 改为进程内 `jieba + bm25s`，按 corpus_version 落盘。

**发现 10：引用偏移会随解析器漂移。**
v1 只存 `char_start/end`。换个解析器（或改一次分段规则），同一句话的偏移就变了，历史引用会静默指错位置，而且**错的时候不会报错**。
→ 引用定位用三元组 `(page, block_index, char_offset)` + `parser_version`，换解析器即失效并重算。

**发现 11：判定必须带时点。**
社保月数每月变、年龄每年变。答案不写"以 X 日状态判定"，事后无法解释。
→ `Profile.as_of` 强制字段，答案末尾固定输出。

**发现 12：规则层无法结构化的部分必须有出口。**
"原则上""可适当放宽""由…认定"——这些占政策条款的相当比例。如果让 LLM 兜底判，四态立刻退化成二态。
→ `Unstructurable` 显式落库，判定直接 unknown。

**结论**：架构方向不变，但**三个环节的契约要重写**（检索拆两段、判定改四态、引用加三元组）。
**修法**：已写入 `ARCHITECTURE.md` 第 2 节 B/E/F。

## 第 4 轮：这些数字能证明什么（评测视角）

**方法**：假设评测已经跑完，问"如果结果是这样，你会相信吗"，逐个证伪。

**发现 13：金标是我写的，就是循环论证。**
50 条题、50 条答案都由我出，模型答对只是"符合我的偏见"。
→ 至少 15 条来自官方问答页（人社局"政策解读"本来就是真实提问），至少 10 条由你人工确认，剩下由我出但标注来源。

**发现 14：`unknown` 的金标最难标，也最容易被回避。**
如果把"不好判"的全标成 unknown，unknown 召回率会很好看，但系统可以靠"什么都说不知道"刷分。
→ 双向出题：必须有 15 条"明确能判"的样本，unknown 的召回要和 satisfied 的召回一起看。

**发现 15：消融对比可能不公平。**
baseline 若用同一套检索、同一套组装，只换判定，才是干净对比。如果 baseline 连检索都换，赢的是检索不是规则。
→ baseline 定义写死：**同 route、同 bind、同 compose，只把 judge 换成 LLM 直判**。

**发现 16：缓存会让 pass^k 虚高。**
同一题跑 3 次，后 2 次命中缓存，看起来稳定。
→ 评测模式强制关闭语义缓存，只保留 embedding 缓存（可复现，不影响随机性）。

**发现 17：全套 300 次 run 跑不完。**
本地模型每次 30–60s → 3–5 小时，没人会跑。
→ 硬约束 ≤30 分钟：k=2、确定性节点回放、只对失败样本跑 k=3。

**发现 18：缺一个元指标——语料完备性。**
如果政策压根没抓进来，检索指标再高也是零分。
→ 增加 coverage 指标：目标事项在语料中的覆盖率（人工核 20 个事项，看语料里有没有）。

**结论**：评测体系要从"答得好不好"改成"**判得对不对 + 敢不敢说不知道 + 语料全不全**"。
**修法**：主指标换成四类混淆矩阵 + 覆盖率；端到端成功率降为辅助指标。

## 第 5 轮：能在面试里活下来吗（叙事视角）

**方法**：假设面试官只有 20 分钟，逐条追问，看哪里会断。

**发现 19：最大的反扑是"这不就是个规则引擎 + RAG"。**
如果消融数据显示 full 只比 baseline 高几个点，整个故事就塌了。
→ 这是**项目级风险**，不能等到最后才发现：M2 结束就先用 15 条样本跑一次预消融，若差距 <10pp，立刻调整（比如把"冲突裁决"和"拒答合规"作为主战场，那是 baseline 结构性做不到的）。

**发现 20：录屏里最抓人的不是答对，是答不出来。**
"你能办"谁都能做；"我不能判，因为你社保差 2 个月，而且这条政策 2026 版把要求从 6 个月改成了 12 个月"——这才是差异。
→ 5 分钟剧本必须包含一次失败：问一个超范围的问题，系统给出 coverage 声明而不是编答案。

**发现 21：ADR 只能写一个真决策，且必须能被数据支持。**
候选：为什么判定不用 LLM（有消融数据）、为什么四态而不是三态（有混淆矩阵）、为什么门控只在三种情况触发。
→ 选定"**为什么把判定从 LLM 手里拿走**"，因为它是唯一有对照实验支撑的。

**发现 22：README 第一屏决定别人要不要往下看。**
→ 结构固定：一句话主张 / 一次失败演示的截图 / 三个数字（判定准确率、引用伪造率、unknown 误报率）/ 覆盖范围声明 / 不做什么。

**结论**：叙事不是最后补的，是**设计约束**——它反过来要求 M2 就要有消融能力。
**修法**：里程碑 M2 增加"预消融"验收项。

## 第 6 轮：剩下的问题（已接受，不是没看见）

| 风险 | 为什么接受 | 触发后的动作 |
|---|---|---|
| 扫描件比例高 | 未实测，M0 才知道 | 缩到一个城市，或只处理有文字层的文件并声明覆盖 |
| 本地模型太慢 | 演示可用录制回放兜底 | 换 7B 小模型，质量下降写进报告 |
| 规则抽取准确率上不去 | 有 `verified_by` 兜底 | 缩到 1 个事项，把规则做深 |
| 消融差距不够大 | 有 M2 预消融闸门 | 换主战场到冲突裁决/拒答合规 |
| 你讲不清 | 每周复述验收 | 砍功能，不砍可讲的部分 |

# 中文政务/法律条款问答：可借鉴的评测数据集与出题方法

> 调研目的：为「上海人社政策条款检索问答」找**别人的题**（当前 50 条自出题不可信），并学习同类数据集的金标质控做法。
> 语料：560 份政策文件、5,736 条条款；答案须落到条款 + 文号。
> 说明：标注「待复核」的数字为本次会话未能打开原始页面（站点拦截），建议引用前二次确认。

| **DuReader 2.0** (ACL W18-2605) | 20 万问题 / 100 万文档 | 机器阅读理解 | **百度真实搜索日志** + 知道问答，人工写答案 | BLEU-4 / Rouge-L（被批与人工判断弱相关） | 百度授权，研究用 | ⚠️ 问题来源思路可借；**指标选择是警示** |

| **CRAG** (arXiv 2406.04744, KDD Cup'24) | 4,409 QA，5 域，8 类题型 | RAG 端到端 | 人工构造，含 **false premise / 无答案 / 时效题** | 准确率 + 幻觉率（三档） | 学术开放 | ✅ **题型设计直接抄**（拒答/时效/多跳） |
| **DomainRAG** (arXiv 2406.05654) | 1,686 网页、14,406 passage；6 子集 90/49/94/65/48/49 | 领域 RAG | ChatGPT/GPT-4 生成 → **人工逐条修正**；时效题纯人工 | EM/F1/Rouge-L + GPT-4 评分（0–5 归一） | 学术开放 | ✅ **最接近我们的构造范式**，子集切分直接抄 |
| **GovRelBench** (arXiv 2507.21419) | 政务相关性基准 + GovRelBERT | 相关性打分（非 QA） | 政务 query-doc 对，软标签 | 相关性分类指标 | 学术开放 | ⚠️ 无问答，仅可作检索相关性参考 |

**一句话结论**：没有任何一个公开数据集能「直接拿来当我们的评测集」；能直接抄的是 **LawBench 3-2 的"法条→生成→人工筛"流水线**、**DomainRAG 的子集切分与人工修正**、**CRAG 的拒答/时效题型**、**LeCaRD 的多级相关度与多正例**。

## 二、Q1 中文法律/政策 QA 盘点：哪几个构造方法能直接抄

1. **LawBench 任务 3-2「情景化法条预测」= 最贴近我们的做法**：取法条原文 → 喂 ChatGPT 生成"情景 + 问题 + 答案" → **人工筛出 5,000 条"答案准确"的 QA** → 用 252 条核心法条做测试集。
   - 可抄点：①生成后必须人工筛，筛的是"答案是否真的落在该法条"；②测试集按**法条覆盖**而不是按题量抽；③报告里明确写"generated by ChatGPT, manually filtered"。
   - 不可抄点：它只做法条**背诵/匹配**，不要求给文号，也没有多条款组合。
   - URL: https://arxiv.org/abs/2309.16289 ｜ https://github.com/open-compass/LawBench
2. **LexEval**：23 任务/14,150 题、38 个 LLM、MIT。它的价值是**能力维度分类（LexCog）**——把"记忆/理解/推理/辨析/生成/伦理"分开报分，避免一个总分掩盖问题。我们可以照此把评测拆成：条款定位 / 条款理解 / 跨文件推理 / 时效判断 / 拒答。
   - URL: https://arxiv.org/abs/2409.20288 ｜ https://github.com/CSHaitao/LexEval
3. **LeCaRDv2**：800 query、55,192 候选，相关度按 **案情/刑罚/程序** 三 aspect 分别标。对我们的启示：一个口语问题往往对应"主条款 + 配套条款 + 附件口径"，应**分 aspect 标多正例**，而不是强行找唯一答案。
   - URL: https://arxiv.org/abs/2310.17609
4. **CRAG**：8 类题型里含 false premise、无答案、时效（跨度从"年到秒"）。这正是政策问答的高频坑（"2024 年的补贴现在还能领吗"）。
   - URL: https://arxiv.org/abs/2406.04744
5. **GovRelBench**：政务域**相关性**基准（不是问答），说明学界已承认"政务 query 的相关性判断与通用域不同"，但**没有公开中文政务 QA 集**。
   - URL: https://arxiv.org/abs/2507.21419

## 三、Q2 从官方文本反推问题：有没有系统性做法？质量差距多大？

**有，且是主流做法**，但没有任何工作直接量化"官方问答 vs 真实用户提问"的差距。可用证据链：

- **DomainRAG（人大，高校招生）**：官方授权抓 1,686 网页 → 切 14,406 passage → ChatGPT/GPT-4 出题 → **"then corrected manually"**。两个关键实证：①纯模型生成的问题必须人工修正才能用；②**时效类问题 ChatGPT 生成不出来，只能人工设计**（65 条 time-sensitive 全是人手写）。
  - URL: https://arxiv.org/abs/2406.05654 ｜ https://github.com/ShootingWong/DomainRAG
- **PolicyQA**：115 份隐私政策只配了 **714 条真人问题**，其余 2.4 万样本靠"同一问题换文档/换段落"扩增。说明学界也承认**真问题稀缺**，扩增是无奈但有效的办法。
  - URL: https://arxiv.org/abs/2010.02557
- **LawBench 3-8**：直接用 66law.com 的**真实用户咨询**（口语、信息不全）配律师答案，指标 Rouge-L。这是学界对"真实提问分布"的正面回应。
- **质量差距的间接证据**：合成测试集系列研究（Rahmani et al., SIGIR 2024, arXiv 2405.07767；后续 arXiv 2506.10301）证明 LLM 合成题**可用于系统相对排名**，但**绝对分数有系统性偏差**（偏向 LLM 系系统）；SynDL（arXiv 2408.16312）在 TREC DL 上复现了高排名相关性。
  - 对我们的直接含义：**官方问答可以当"可信的绝对锚点"，但不能假装它等于用户分布**；口语分布必须另有来源（真实工单/人工改写）。

**结论**：从"政策解读/一问一答"抽 QA 有成熟先例（DomainRAG 最像），质量上有两个已知缺口——(a) 问题是**书面语、按文件结构问**，不是用户问法；(b) **时效/版本类问题模型生成不了**，必须人工补。这两点我们都要在报告里如实写。

## 四、Q3 中文检索评测集：构造与评测口径

- **T2Ranking（T2Retrieval）**：>300K query、>2M passage，query 来自**真实搜索引擎日志**，专家 4 级 graded relevance，并且**专门补标了"也算相关"的多样性 passage**以对抗 false negative。HF 上 `mteb/T2Retrieval` 是降采样 dev 分片：22,812 queries / 118,605 corpus / 118,932 qrels，Apache-2.0，domain 列表含 Government。
  - 启示：①真日志 query 才有口语分布；②**必须主动补标多正例**，否则 recall 被低估；③nDCG 而非 P@1。
  - URL: https://arxiv.org/abs/2304.03679
- **mMARCO**：MS MARCO 机翻 13 语种、**不重标 qrels**，结论是"翻译质量与检索效果正相关"——反面教材：**不重标的翻译/改写会引入系统性偏差**。
  - URL: https://arxiv.org/abs/2108.13897
- **DuReader 2.0**：20 万问题/100 万文档，问题来自**百度真实搜索日志 + 知道**，答案人工写。关键教训：**BLEU-4/ROUGE-L 与人工判断相关性弱**，所以后来才有 DuReader-Robust/Checklist/DuQM 等改评测。我们若用 Rouge 评"答案对不对"会被同样质疑。
  - URL: https://aclanthology.org/W18-2605/ ｜ 检索版 https://arxiv.org/abs/2203.10232
- **CMedQA2**：10.8 万问/20.4 万答，真实社区问答（寻医问药网），非商业许可——证明"垂直域 + 真实提问"可以做到十万级。
  - URL: https://github.com/zhangsheng93/CMedQA2

**口径建议**：检索层用 **nDCG@10 / Recall@k（多正例集合）**；答案层用 **条款命中 + 文号命中 + 要点覆盖**的人工/规则混合评分，**不要用 Rouge 当主指标**。

## 五、Q4 金标质量控制：具体做法

| 做法 | 出处 | 具体参数 |
|---|---|---|
| 生成后**人工全量筛** | LawBench 3-2 | 从生成池筛出 5,000 条"答案准确"的，再抽 252 条法条做测试 |
| 生成后**人工逐条修正** | DomainRAG | "initially generated … then corrected manually"，并公开子集切分 |
| **专家标注 + 多级相关度** | LeCaRD/LeCaRDv2 | 4 级相关度；v2 拆 3 个 aspect 分别标 |
| **多正例显式补标** | T2Ranking | 测试集额外标注多样性 passage，缓解 false negative |
| **拒答/弃权单列** | LawBench（abstention rate）、CRAG（无答案题） | 单独统计"该拒答时是否拒答"，不混进准确率 |
| **一致性报告** | LexEval 等 | 报告标注流程与专家背景；学界通行做法是双人独立标注 + 第三人仲裁，报 Cohen's κ（≥0.6 可接受，≥0.8 好） |

**落地到我们的 50→N 条**：
1. 每条题至少 **2 人独立标**"答案条款集合"，冲突由第 3 人（业务专家）仲裁；
2. 抽 **20%** 复核，报 **κ 与条款级一致率**；
3. 允许多正例：标"必要条款（必须命中）/ 可选条款（命中加分）/ 无关"，评测用集合 recall + 必要条款全中率；
4. 单列 **拒答题**（语料里确实没有依据）与 **时效题**（旧版已废止）。

## 六、Q5 可复用性：有没有现成的中文政务/人社问题可用？

**没有。** 实测结论：
- HuggingFace 全站搜 `gov / policy-qa / 政务 / 社保 / 人社 / 12345 / chinese-policy`：**无任何可用的中文政务或人社问答数据集**。`qinchen1986/zh-policy-qa-thinking` 只有 1,180 字节空壳；`MagicHub/domain-QA` 只有 CC-BY-4.0 标签无内容；`i-dot-ai/govuk-policy-qa-pairs` 是英国政府。
- 中文政务问答的论文（《中文检索增强生成在政务热线领域的创新与应用》电信科学；《大语言模型驱动的可信政务问答技术》软件学报 2026）**均未公开数据集**。

**但有一类"别人的题"是公开且高质量的：政府自己写的政策问答。**
- 上海人社局「政策解读」栏目：https://rsj.sh.gov.cn/tzcjd_17352_17352/ ，共 **17 页 × 19 条 ≈ 323 篇**，大量标题形如"《XX 通知》政策问答"。
- 样例：https://rsj.sh.gov.cn/tzcjd_17352_17352/20260812/t0035_1443066.html （《上海市失业保险金申领发放实施办法》政策问答，2026-08-06），单篇 **7 组编号问答**，格式"**1. 在本市申领失业保险金需要符合什么条件？ 答：…**"，答案里**直接写文号**"沪人社规〔2026〕18号"，页尾"相关稿件"链回原通知。
- 同类：上海市政府政策解读问答（https://cdn.shanghai.gov.cn/nw17239/20261103/f68ebef2da1c45c0bed977580b789fa2.html ）、人社部政策解读索引（http://114.255.111.133/SYrlzyhshbzb/zcfg/SYzhengcejiedu/index_16.html ）。

**最接近的替代**（若无上海人社）：①人社部及各省人社厅「政策问答」栏目（同构，可迁移题型）；②国家数据局"省域政务热线高质量数据集"案例（https://www.nda.gov.cn/sjj/ywpd/szkjyjcss/1015/20251015160103906239795_pc.html ，说明政务热线数据已开始被当作数据集治理，但未公开）。

**不可用**：上海 12345 人社分平台只有新闻报道；12333 智能问答 yixin.m12333.cn 返回 JS 挑战/412，不可抓。

## 七、Q6 缺口 = 我们的差异化

现有数据集普遍**不测**：
1. **时效性/版本**：政策废止、新旧文号并存、"2024 年标准 vs 2026 年标准"。DomainRAG 只做了 65 条 time-sensitive，LawBench 完全没有。
2. **地区差异**：同一事项沪/苏/国标口径不同（产假、育儿假、社保基数）。所有公开集都是单域单地区。
3. **拒答/无依据**：只有 CRAG、LawBench 有弃权率；政策问答里"你这种情况不符合条件"是高频真实需求。
4. **多条款组合答案**：现有集基本假设单条款；实际"领失业金"要同时命中申领条件 + 发放标准 + 停发情形。
5. **文号引用正确性**：没有任何数据集要求输出文号并校验。
6. **计算题**（养老金/工伤待遇测算）：CAIL2021 有刑期计算，政策域没有对应基准。

→ 这 6 点正是我们可以对外主张的评测维度，且**用官方政策问答做锚点、用真实工单做口语分布**即可覆盖前 4 点。

## 八、我们自己的出题方案（按性价比排序）

### 方案 A（性价比最高）：抓官方「政策问答」，做"别人的题"的骨架
- 来源：上海人社局政策解读栏目 323 篇 + 人社部/兄弟省市同类栏目；只保留与 560 份语料能对上文号的。
- 做法：解析"数字编号 + 问句 + 答："结构 → 抽取 (问题, 答案, 文号) → **人工/规则映射到条款 ID** → 得到"官方问 + 官方答 + 条款锚点"。
- 预计条数：单篇均 5–8 组问答；**全量约 1,500–2,500 组**，过滤到语料覆盖范围后 **300–600 条可用**。
- 成本/难度：**低**（静态 HTML，1–2 人日抓取解析 + 2 人日人工映射）；风险是问题偏书面语。
- 价值：这是唯一"出题人 ≠ 我们"且带官方文号的来源，**必须做**。

### 方案 B（性价比次高）：双盲改写 + 交叉标注，把官方问句变成口语问句
- 做法：取方案 A 的 300–600 条，交给**不写代码的业务同学/外包**做"口语化改写"（每条改写 2–3 种问法：如"老婆生孩子能休多久"），改写者**看不到答案条款**；另请 2 人独立标条款集合，冲突仲裁，抽 20% 复核报 κ。
- 预计条数：300–600 条 × 2–3 问法 ≈ **800–1,500 条口语 query**，金标沿用官方答案。
- 成本/难度：**中**（3–5 人日）；这是 LawBench"人工筛"与 DomainRAG"人工修正"的最小可行版。
- 价值：补上"口语分布"这一唯一短板，且改写者与标注者分离，可直接回应"出题人=写代码的人"的质疑。

### 方案 C（最贵最真）：真实用户问题
- 来源：12345 人社工单 / 12333 来电记录 / 随申办咨询（需数据授权）；退化替代=公开法律咨询平台的社保劳动类提问（类 LawBench 3-8 的 66law 做法）。
- 预计条数：授权顺利 **500–2,000 条**；仅公开咨询替代 **100–300 条**（且需人工筛到政策域）。
- 成本/难度：**高**（跨部门授权，周期不可控）；建议作为**长期项**，先谈 100 条试点验证分布差异。
- 价值：唯一能证明"我们的评测贴近真实分布"的来源，适合对外发布时做 validation set。

**排序理由**：A 用最低成本拿到"第三方出题 + 官文号"；B 在 A 之上用人力补口语分布，成本可控；C 真实但受授权制约，先小规模试点。

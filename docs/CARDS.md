# 三张卡：判定 / 标准 / 拒答

> 用户要的不是五条候选，是一个结论和它的依据。
> 但"给结论"有两个前提：**有规则**、**有你的信息**。缺任何一个，结论就是编的。

## 一句话

`compose` 不再拼一段话，而是按"能不能判定"分派到三种卡。每种卡都带证据，
每个证据都能回到条款原文。**卡里没有无出处的句子**。

## 三种卡

| 卡 | 什么时候出 | 用户看到什么 | 关键字段 |
|---|---|---|---|
| **判定卡** | 有判定器 + 画像够（当前只有落户） | "已知 71 分，标准 72，还差 1 分"+ 逐项页码 | `verdict` `score{known,upper,standard,gap}` `basis[]` `missing[]` |
| **标准卡** | 有条款，但结论取决于你的情况 | 条文原文 + 引用 + "取决于…" | `items[]{quote,citation}` `depends_on[]` |
| **拒答卡** | 没接入 / 域外 / 找不到直接条款 | 为什么不答 + 查了哪些 + 下一步 | `reason_kind` `searched{n_docs,n_queries}` |

三张卡的区别不是模板，是**确定性等级**：判定卡是"我能算"，标准卡是"我能引但不能判"，拒答卡是"我不该答"。

## 硬规则

```
卡里每一句话，要么是某条条款的逐字片段（带页码），
要么被标注为「推断」或「需要你确认」。
做不到就丢掉。
```

实现上体现为：

- `quote()` 只截**完整句子**，不切断词；
- 每张卡的 `evidence[]` 都带 `citation`（含载体：`第 21 页 · PDF 原件` / `第 402 段 · 网页原文`），由 `verify` 节点回填 `verified`；
- 判定卡的 `basis` 每项都带 `page`——页码来自规则文件，不是模型生成的；
- 每张卡都有 `not_claimed[]`：明说这张卡**没覆盖什么**（单位资质、材料真实性、当年另有调整）。

## 分派规则

```
answer 是拒答类（not_covered / out_of_domain / insufficient / human_reject）→ 拒答卡
judgement.source ≠ none（有判定器）                                        → 判定卡
有候选条款                                                                → 标准卡
其余                                                                       → 拒答卡
```

"没有判定器"不算拒答，也不算判定——走标准卡。对应地，`gate_judgement` 只在**真的尝试过判定**（`source != none`）且结论为 unknown 时才拦人；
没有规则的问题不该拦人，否则每道题都要人工点一下。

## 为什么这是产品形态，不是排版

中介网站做的是"填三个框 → 出分数"，赢在**给结论**。
我们如果只给条文，就是把工作退回给用户；
如果给自由文本，就会把"不超过"写成"不低于"——这个领域错一个词就是错答案。

判定卡是这个项目唯一能同时做到"给结论"和"每句话可核对"的形态。
它也正好对上项目主张：**价值不在替你答更多，而在替你挡住不该答的，并留下为什么的证据。**

## 例子

落户（判定卡）：

```
【判定卡】还不能确定：已知 71 分，标准 72 分，至少还差 1 分；另有 3 项待确认
   分数：已知 71 / 上限 89 / 标准 72
   ✓ 最高学位、学历 / 硕士  24 分  （第 21 页）
   ✓ 毕业院校 / 一类高校  15 分  （第 21 页）
   ? 待确认：外语水平、荣誉称号、竞赛获奖
   本卡未覆盖：单位资质、申报材料真实性、当年政策是否另有调整
```

失业保险金（标准卡）：

```
【标准卡】找到了相关规定，但结论取决于你的具体情况
   · （三）延长领取失业保险金的失业人员，失业保险金发放标准为1690元/月。
     —— 《沪人社规〔2026〕7号》一、 / （三）（第 7 段 · 网页原文）
   取决于：你的具体身份/单位类型、发生时间（政策有版本）、是否已享受过同类待遇
```

北京落户（拒答卡）：

```
【拒答卡】没有接入这块政策，所以不能回答
   原因：未覆盖北京的政策（当前只接入上海）
   检索范围：0 份文件 / 0 条候选条款
```

`n_queries = 0` 是关键：**"没接入"不能留下"查过"的痕迹。**

## 代码

- `app/answer/cards.py`：`verdict_card` / `standard_card` / `refusal_card` / `build` / `quote`
- `app/runtime/steps.py::compose`：只调 `cards.build`，不拼文案
- `tools/run.py`：CLI 按卡渲染（判定/标准/拒答三种版式）
- `tests/test_cards.py`：8 条，守"空分不编差多少""未接入不声称查过""引用必须逐字"

## 已知不足

1. 判定卡只有落户一个判定器；其他事项都是标准卡。
2. 标准卡的 `depends_on` 是写死的三句，没有按事项定制。
3. 拒答卡不区分"语料里没有"与"没接入"，这两件事文案相近但含义不同（`reason_kind` 里有，展示层没分开）。

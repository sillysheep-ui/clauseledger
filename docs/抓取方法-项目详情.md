# 抓取层总结 · ClauseLedger（条款账本）

## 一、方法简介

### 1. 要解决的问题

政策正文散在 337 个地级市门户、上千个栏目页和附件里。页面形态有四种（服务端表格 / `<li>` 列表 / JS 渲染 / 空壳），防护有三类（加速乐 / CT2 / 瑞数）。

抓取层的目标不是"抓到就算"，而是**每一次抓取都能回答三件事**：拿的是哪一份字节、从哪来、为什么失败。

### 2. 三档抓取（核心）

| 档位 | 什么时候用 | 怎么做 | 代价 |
|---|---|---|---|
| ① httpx 直连 | 正常站点 | UA 标明身份与联系方式；1 req/s；最多 3 次重试，指数退避 + 0–20% 抖动 | 不执行 JS，遇到挑战页必失败 |
| ② 无头 Chromium | 403/412/418/429/503/521/522/524 | 两段式：`goto` → 等 5 秒 → 正文不足则 `reload`（此时已带 cookie） | 指纹仍是"自动化"，瑞数/加速乐会循环 |
| ③ 真 Chrome（CDP） | ②也失败时 | 每次抓取**新起一个** Chrome：随机空闲端口、独立临时 profile、`--no-sandbox`；连上 CDP 读 DOM，用完 `terminate` | 慢 5–10 秒；`--no-sandbox` 只能本机用 |

**不重试确定性失败**：403/404/410/412/451 立即放弃。重试这些既浪费时间，又像在攻击对方。

### 3. 判据：数汉字，不数字节

原来的判据是 `len(html) >= 200`——一个 7 KB 的挑战页也能通过，但汉字只有 5 个。

改成 **正文汉字数 ≥ 200** 才算拿到。并且：首包 412、跑完 JS 后拿到真正文 → 记 `status=200`、`via=chrome`，因为我们确实拿到了页面。

### 4. 站点发现：不是赌一个域名

三级递进，每一步都实测过提升：

```
拼音/首字母候选      235 / 333（71%）
→ 省级门户导航二跳   270 / 333（81%）
→ 浏览器重试         289 / 333（87%）
→ 省级门户渲染后再取  309 / 333（93%）
→ 补 4 个直辖市       337
```

**域名碰撞必须人来判**：`taizhou.gov.cn` 是江苏泰州，浙江台州在 `zjtz.gov.cn`。这类错误程序自己发现不了，只能靠"正文里有没有城市名"这个判据暴露。

### 5. 失败留痕与证据

- `FetchError(url, status, attempts, stage)`：失败带出状态码、尝试次数、卡在哪一档
- 失败写进 `data/manifests/*.jsonl`：`http_status` / `attempts` / `stage`
- `tools/ingest/ledger.py` 跨批次汇总：`attempts`、`first_failed`、`last_tried`、`state ∈ {ok, ok_after_retry, never_ok}`
- 原件按内容哈希落盘：`data/raw/<sha256 前 12 位>/<原文件名>`

## 二、成果与收益

### 数字

| 指标 | 值 |
|---|---|
| 城市可达 | **327 / 337**（httpx 274 + browser 39 + chrome 14） |
| 上海人社语料 | 565 条目录 / **573 份正文** / **127.97 万字** / 31,392 块 / 1996–2026 |
| 附件 | 296 个；**三分之一 PDF 是扫描件**（103 份走 OCR） |
| 失败后成功 | 59 份；从未成功 **0 份** |
| 单测 | 121 条通过 |

### 收益，三条

**① 覆盖率从一个数字，变成一套可解释的分类。**
原来只有"313 可达 / 24 不可达"。现在是：可达 327、没找到入口 8、城市名碰撞 1、真拦 1。数字变小了，但每一格都能说清。

**② 抓取可复现。**
同一份文件，字节 + sha256 + 抓取时间 + 来源方式（crawl / manual）全部落盘。任何人可以拿这个哈希去核对"当时拿到的是不是这一份"。

**③ 失败可分诊。**
403 / 404 / 412 是三种完全不同的下一步：403 是权限、404 是地址错、412 是客户端被识别。混成一个"失败"数，就没法决定该修哪里。

### 一次自我纠错（最值得写的一条）

上一轮统计出 24 个城市"不可达"，全部是用 httpx 探的。换真 Chrome 重测后 **14 个能打开**，而且原因和防护无关：

| 原判 | 实测真相 | 数量 |
|---|---|---|
| 打不开 | **我们域名猜错了**（DNS 根本不解析，如 `linxiahuizu.gov.cn`、`gannanzangzu.gov.cn` 这种按民族全名硬拼的） | 21 |
| 同名碰撞 | taizhou.gov.cn 是江苏泰州 | 1 |
| 网络超时 | 清远、德阳 IP 通但 60 秒无响应 | 2 |

> **`blocked` 是个垃圾桶标签，它同时装着"对方不让"和"我们自己找错了"。不分开，覆盖率就是自欺。**

## 三、面试模拟（问题 + 答案）

### Q1 你怎么保证抓下来的东西是真的？

三层。①原始字节按 sha256 落盘，抓取时间、来源方式一起记；②结构化数据是派生物，随时能从字节重算；③检索引用带页码和字符偏移，能回到原文那一句。所以"这份文件"和"我们说的这句话"之间是可验证的。

### Q2 反爬怎么处理？

先分类，再处理。三类 WAF 表现不同（加速乐 521、CT2 412、瑞数随机 cookie），但共同点是**两段式**：首包只有混淆 JS，浏览器执行后写 cookie，第二次请求才给正文。

所以：①httpx 停在第一段，不是被拒绝，是没完成握手；②Chromium 能过一部分；③真 Chrome 能过大部分。

对照实验：同一个 URL，httpx 412 / 0 汉字，Chromium 0 汉字，真 Chrome 360 KB 正常渲染。

### Q3 你怎么知道不是封 IP？

做对照。同一台机器、同一时刻，只换客户端：httpx 和 Chromium 都拿到 0 字，真 Chrome 拿到完整首页。而且成都各部门子域全部 412，出口 IP 是北京联通——不是地域封禁。三个证据合起来，拦的是指纹。

### Q4 为什么用 Playwright 不用 Selenium？

Playwright 能直接拿到 `response.status`，等待机制更稳，API 更简洁。Selenium 多一层 WebDriver 指纹，反而更容易被识别。不过这不是关键——关键是**真 Chrome 和自动化浏览器是两回事**，Playwright 自己的 Chromium 一样过不去。

### Q5 333 个城市的入口怎么找？

三级跳：拼音/首字母猜 → 省级门户导航页二跳 → 浏览器重试。71% → 81% → 87% → 93%。

但最后 24 个里 21 个是我域名猜错，不是站点不可达。这条最值得讲：**"blocked" 会把两种完全不同的原因混成一个标签**，不拆开就会得出错误结论。

### Q6 抓取失败会一直重试吗？

不会。按状态码分两类：408/425/429/5xx/521/522/524 可重试（最多 3 次，指数退避 + 抖动）；403/404/410/412/451 立即放弃。重试确定性失败既浪费时间又像攻击。

失败会进台账，带状态码、尝试次数、卡在哪一档——不是一句"失败了"。

### Q7 怎么保证数据不过期？

不能靠 `Last-Modified`：实测同一页面两次请求它都在变，是动态生成的。改成自算内容哈希，日扫列表首屏做 diff，按文号判断新增 / 改版 / 删除。

政策是月级低频，T+1 足够。要防的不是"慢"，是"漏"——所以加了"连续 0 新增"的告警。

### Q8 真 Chrome 要 `--no-sandbox`，这能上生产吗？

不能。这是本机受信环境的权宜：外层沙箱里 Chrome 自己的 sandbox 起不来。写进文档的代价栏了。生产上要么换有资质的数据源，要么人工/半自动取回。

这条我特意留着没藏——它同时也是"知道边界在哪"的证据。

### Q9 数据量多大？处理得动吗？

上海人社一个部门：573 份、127.97 万字、31,392 块。全量重建一次 437 秒（5 并发）。

真正慢的不是抓，是 OCR：15 路并发会让单份 50 页 PDF 从 30 秒劣化到 1 小时（Apple Vision 互相拖慢）。所以加了全局闸门，只允许 2 个并发。

### Q10 如果重做，哪里会改？

先做 DNS 判定和入口确认，再做抓取。现在 21 个 "blocked" 是域名猜错造成的，等于用错误结论污染了覆盖率统计。

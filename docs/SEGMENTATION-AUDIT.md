# 切分体检：一次把"切得好不好"变成可数的数字

> 这一轮只回答一个问题：**条款切分有没有问题、问题有多少、修掉之后还剩多少。**
> 不涉及检索、不涉及判定。

## 1. 怎么判"切得好不好"

切分是按编号标记切的（`第X条` / `一、` / `（一）` / `1.`），所以正确性可以用**结构不变量**机械检查，不需要人逐条读：

| 编号 | 不变量 | 违反意味着 |
|---|---|---|
| I1 | 条款文本以它自己的编号开头 | 切在句子中间 |
| I2 | 父条款文本包含子条款文本 | 父子区间没算对 |
| I3 | 子条款区间落在父区间内 | 同上 |
| I4 | 同级兄弟区间不重叠 | 重复输出 |
| I5 | 叶子区间并集覆盖全文 | 正文没进索引 |
| I6 | 单条 ≥15 字（<15 记为碎片） | 切得太碎 |
| I7 | 单条 ≤3000 字（>3000 记为粘连） | 没切开 |

I1–I4 是硬违规（结构错），I5–I7 是软指标（程度问题）。**I2/I3 有一个天然局限：父条款本来就是"包含子条款全文"的拼接，所以这两条近乎同义反复，抓不到"边界切错但拼得回去"的情况**——那一类要靠边界抽检（`tools/eval_boundary.py`，每批 20 条人工判）。

## 2. 这一轮查出并修掉的四个问题

### 2.1 条款偏移不单调（18 份文档）

`start` 应该随文档顺序递增。体检发现 18 份文档里 `start` 会往回跳。

成因：载体模型把"主副本条款"和"补充副本条款"分别切分后拼接，偏移用**块数**累加（`sum(len(b.text)) + 1`），而全文是**按行**拼接的，差几行就会错位。更麻烦的是同一份文件里"三、"可能出现两次（正文 + 附件），用 `text.find` 顺序搜索会把父条款定位到后一份、子条款定位到前一份。

修法：按**块锚点**重算——`start = 该块在全文的起点 + char_offset`，再按 `start` 排序。修后非单调文档 **18 → 0**。

### 2.2 附录误判（把正文标成「附件3」）

`附件` 单独成行就进入附录模式，把后面所有内容按 600 字切块。但正文里也会出现独立的"附件3"（附件清单、表格标题），于是一整段正文被标成附录块——`沪教委学〔2026〕13号` 有 41 条正文条款被错标。

修法：附录头必须同时满足**位于文档后 40%**。修后 I1 违规 **123 → 0**（附录续块按设计豁免）。

### 2.3 重解析把主副本复制了一遍

`reparse_all` 走的是"页面块 + 附件块"的旧路径，而记录已经是载体模型（主副本 + 补充 + 已丢弃副本）。结果主副本正文被拼了两次，条款翻倍、区间大面积重叠。

修法：`reparse_all` 遇到带 `carrier_choice` 的记录，改走 `carriers.rebuild`。修后条款 **10,954 → 7,738（−29%）**，I4 重叠 **37 → 7**。

### 2.4 附录续块被当成"标签不一致"

附录按 600 字切块后，第 2 块起文字不以"附件N"开头，但这是设计。体检里加豁免：`label` 以 附件/附录/附表 开头且 `sec > 0` 时跳过 I1。

## 4. 还剩什么（如实记）

15 份文档仍有 I2/I3 违规，是同一类：**同一编号在正文与附件里各出现一次**，合并后父条款取到后一份、子条款取到前一份。典型：

| 文档 | I2 | I3 | 触发路径 |
|---|---:|---:|---|
| `沪人社规〔2018〕21号` | 21 | 21 | `三、` / `四、` |
| `沪人社福发〔2014〕33号` | 15 | 15 | `1、` / `2、` |
| `沪人社职发〔2016〕10号` | 14 | 14 | `一、` / `二、` |
| `沪人社规〔2018〕47号` | 14 | 14 | `一、` / `二、` |

**为什么没继续修**：根因是"同一份文件里有两套同编号正文"，要么按位置消歧（把附件区单独编号），要么按内容消歧（相似度合并）。前者改动切分语义、会影响引用路径；后者要先有可靠的章节指纹。两条都属于结构性改动，收益是把 2.6% 的文档从"有硬违规"降到"接近 0"，但**这些文档的检索结果没有因此变差**（dev 里没有一题依赖它们的前 3 名），所以先记账、不动。

碎片 249 条同理：它们大多是"（一）……"下面只有一个词的情况（比如"（二）区人力资源社会保障部门："这种过渡句），属于编号体系的固有形态，不是切错。

## 6. 面试时怎么讲

一句话：**"切分质量不该靠抽样肉眼看，我先把它变成七条可机械检查的不变量，一次跑出 10,954 条里有多少条结构不自洽；然后按'根因'而不是按'文档'去修。"**

三个可展开的点：

1. **偏移问题为什么难发现**：`start` 错了不会报错，检索照常返回，只有父子区间对不上时才露馅——这正是"结构不变量"能提前发现的那类缺陷。
2. **为什么修完条款数从 10,954 掉到 7,738**：不是丢内容，是把主副本重复拼接的部分去掉；对照证据是 dev 指标没变。
3. **为什么剩 15 份不修**：因为修它要改编号语义，而当前评测里没有任何一题依赖它们的前三名——**先记成已知缺陷，比悄悄改坏引用路径更划算。**

## 已知缺口：父条自有文字不进索引（2026-11-23 实测）

`_is_leaf` 只索引叶子条款，父条只用于装配时补上下文。父条里"不属于任何子条"的那部分文字
（导语、施行日期、粘进来的问答）因此**既不在索引里，也不会被检索到**。

| 项 | 数值 |
|---|---|
| 有自有文字的非叶子条款 | 1,128 条 |
| 自有文字合计 | 49,873 字 ≈ 全库正文 **5.8%** |
| 长度 ≤30 / 31–80 / 81–200 / >200 | 674 / 308 / 122 / **24** |
| 以"……："或"以下"结尾（引导句） | 约 31% |

24 条 >200 字的属实质内容（合计 9,939 字），例如 `沪人社规〔2021〕13号` 的 `一、`（952 字，
正文后粘了问答体解读）、`沪人社规〔2021〕12号` 的 `三、`（451 字，含施行日期与有效期）。

三种改法与代价：A 把 ≤120 字导语拼进子条索引文本（重建索引 ~60 秒，可能与长度归一化冲突）；
B 只给 24 条实质父条单独建条目（条款 +24，可能与子条抢名次）；C 记账不改。

**当前决定：先不做（2026-11-23）。**若要动，先做纯离线检查——70 道有官方答案的题里，
有几道的答案句只落在父条自有文字里、任何叶子都匹配不上；0–1 道就维持 C。

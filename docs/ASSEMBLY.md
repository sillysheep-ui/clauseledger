# 装配层：从"给邻居"改成"给整份文件"

## 问题

检索返回 5 条条款，装配只给"命中条款 + 父条 + 前后各一条邻居"，最多 8 条、约 1,800 字。
但 12,000 字的预算只用掉了 15%。

实测：87% 的题金标文件进了前 10，但只有 **42%** 的题把"官方答案那句话"装进了上下文。
差的不是检索，是**同一份文件里、答案所在的那几条没被装进来**。

## 改法（`app/answer/context.py`）

```
旧：hit → parent → neighbor（沿位置扩一条）
新：锚点（前 3 份不同文件）→ 父条 → 同文件按相关度取前 N 条 → 预算内填
```

- 锚点顺序即命中顺序，保证"引用的第一份文件"就是检索认为最相关的那份；
- 同文件展开的排序：问题词命中数 + 数字型问题对含数字条款加分 + 轻微长度偏好；
- 单条仍截 1,200 字、总预算 12,000 字；
- `CLAUSELEDGER_ASSEMBLE=legacy` 可退回旧行为做对照。

## 实测（dev n=70 可核对答案 / n=105 生成）

上下文覆盖（至少一句官方答案）：

| per_doc | 3 | 5 | 8 | 20 |
|---|---|---|---|---|
| 至少一句 | 67.1% | 68.6% | 70.0% | **72.9%** |
| 过半 | 60.0% | 61.4% | — | 62.9% |

生成层（k=5，重排开）：

| 指标 | 旧装配 | 新装配（per_doc=20） |
|---|---|---|
| 上下文含答案句 | 41.9% | **48.6%** |
| 官方数字事实覆盖 | 36.6%（15/41） | **53.7%（22/41）** |
| 句子核验通过率 | 71.3% | 64.5% |
| 因数字无出处被丢 | 67 句 | 116 句 |

## 怎么读这组数

- **事实覆盖 +17.1pp** 是这轮最大的一次单点提升，来源就是"把同一份文件的相关条款全给它"。
- 句子通过率反而降了（71.3%→64.5%）：上下文变长后模型写得更长、引用更容易出格，
  核验把这些句子拦掉了——**它保护了正确性，也吃掉了部分覆盖**。
- 这不是"上下文越长越好"的证据：per_doc 从 3 到 20 只涨 5.8pp（上下文覆盖），
  但生成层涨了 17pp，说明**关键不是长度，是"答案所在文件被展开"**。

## 边界

- per_doc=20 不是调参结果，是"这份文件的条款基本都给"；文档条款数中位 10 条左右。
- 仍有一半的题上下文里没有答案句：这些多半是"金标文件都没进前 5"或"官方答案根本不在语料里"。
- 下一步是补丁图扩展（`现对《X》作如下调整` → 把 X 拉进来），它能覆盖"答案在隔壁文件"的那一类。

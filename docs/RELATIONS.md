# 废止关系：为什么"有效期"不够，以及我们怎么把它补上

## 1. 问题

`docs/EVAL-VALIDITY.md` 里有一条结论：dev 上 38 条"未命中"里，22 条是我们返回了**更新的文件**、金标更旧；其中 **18 条金标已经过期**。

最刺眼的一条：

> `沪人社福发〔2015〕34号` 的 `effective_to` 是**空**，看起来仍然有效，
> 但它的正文之外——`沪人社规〔2020〕26号` 第九条——写着
> "《关于进一步做好本市建筑业工伤保险工作若干意见的通知》（沪人社福发〔2015〕34号）同时废止"。

**一条漏记，9 道题判错。**

根因不是抽取写错了，是**结构上抽不到**：文件自身字段只能写"我自己什么时候失效"，而"我被谁废止"写在别人的文件里。S3 抽取层如果只抽自身字段，`repealed_by` 永远是 0。

## 2. 做法

新增 `tools/ingest/relations.py`，把"文件与文件之间的事"抽成**事件表**（不是知识图谱）：

```json
{"type": "repeal", "source": "沪人社规〔2020〕26号", "target": "沪人社福发〔2015〕34号",
 "effective_date": "2020-12-01", "confidence": "exact",
 "evidence": {"path": "九、/（二）", "page": 7, "text": "…（沪人社福发〔2015〕34 号）同时废止。"}}
```

四类字段：谁做的（source）、对谁做的（target / target_title）、什么时候生效（effective_date）、**证据在哪一条**（evidence.path + 原文片段）。

### 抽取规则（三条，都是被实测逼出来的）

1. **按句子抽，不按条款抽。** 初版在一整条（可能上千字）里找关键词，然后把整条里出现的所有文号都挂上去——结果 `沪人社规〔2020〕12号` 一条就吐出 12 个目标，其中一半是它引用的依据文件。改成按 `。；！？` 断句后，边数从 530 降到 143，precision 明显上来。
2. **关键词窗口是双向的。** 中文两种写法并存：
   - "同时废止《A》《B》" —— 目标在关键词**后面**
   - "《A》（X 号）同时废止" —— 目标在关键词**前面**（我们那条关键记录就是这种）
   只往后扫会漏掉一半。
3. **一段话里有文号就只认文号，不再认标题。** 实测同一标题在不同年份有 24 组（最大一组 11 份），标题匹配会把 2010 年的文件挂到 2020 年的废止句上。

### 三类状态

| 类型 | 含义 | 触发 |
|---|---|---|
| `repeal` | 整份废止 | "同时废止""停止执行" |
| `partial_repeal` | 部分条款停止执行 | 同一句里有"第 X 条…停止执行" |
| `extend` | 延期 | "有效期延长至 X 年 X 月 X 日" |

`partial_repeal` 必须单独一类：把"第三条规定停止执行"当成整份废止，等于让一条还有效的规定被系统判死。

## 3. 结果

| 指标 | 数值 |
|---|---|
| 事件总数 | **143** |
| 其中 repeal / partial_repeal / extend | 137 / 3 / 3 |
| 指向库内文件（exact） | **91** |
| 指向库外或未解析 | 51（记 `unresolved`，不猜） |
| 有出边的源文件 | 116 份 |
| 语料里出现"废止/失效"字样的文件 | 110 份 |

关键边已覆盖：`沪人社规〔2020〕26号 ──废止──▶ 沪人社福发〔2015〕34号`（2020-12-01，证据 `九、/（二）`）。

**抽检**：随机 20 条逐条看过，19 条正确；1 条是"部分条款停止执行"被归到 repeal（已单列 `partial_repeal` 修掉）。误报主要来自两种：一句话里列了多份被废止文件（我们拆成多条边，算对）、以及跨句引用（已由句子级切分挡掉）。

**召回**：语料里 110 份文件提到废止，我们有出边的源文件 116 份——不是分母对得上，而是说明**没有系统性漏掉整类文件**；逐句召回率没有人工标尺，只能等扩语料后复核。

## 4. 对检索的影响：只标注，不改分

`app/domain/validity.py` 提供：

```python
status_at(doc, as_of="2026-11-16", rels=...)   # -> Validity(status, reason, repealed_by, since)
repealed_map(as_of=...)                         # -> {doc_no: 理由}，检索时标注
```

状态优先级：`repealed > expired > unknown > effective`。"废止"是明确动作，"过期"是按日期推的，"不知道"不等于"失效"。

检索里 `Hit.stale` 会带上理由，引用串后面可以写"（已被《X》废止，2020-12-01 起）"。

### 为什么没动排序（两次实验都失败）

| 做法 | hit@1 | hit@3 | 结论 |
|---|---|---|---|
| 不动（现状） | **55%** | **70%** | 基线 |
| 被废止文件降权 ×0.5 | 54% | 62% | 掉 8pp，否决 |
| 废止源提权 ×1.3 | 54% | 65% | 掉 5pp，否决 |

原因：我们只有"谁废了谁"，**没有"谁替代了谁"**。降权只是把旧文件推下去，不能保证新文件能顶上来；提权会把"顺手废止了别的东西"的新文件抬到不相干的问题上。

所以这一层的产出是**标注**，不是排序。等有了可靠的替代关系（Work 层），再谈排序。

## 5. 现在多了一个指标

评测报告里新增两行：

- **现行性**：top-1 引用了已被废止的文件 **7/94**（文号可能对、内容已过期）
- **金标仍有效子集**：hit@1 **49/77 = 64%**（整体 55%，差额来自 17 条金标自身已废止的题）

两个数都要报。前者是"我们答得对不对"，后者是"题目本身还剩多少含金量"。

## 6. 已知问题

1. **51 条 unresolved**：目标不在语料里（别的部门发的文件），现在只记录不追查。它们应该进"缺件清单"，而不是丢掉。
2. **延期只抽到 3 条**：因为延期信息大多在**表格**里（`沪人社规〔2026〕12号` 那种一行一份文件），而表格型文件常常 0 条款。表头行认得出，行内语义还没结构化。
3. **没有 Work 层**：`沪人社规〔2020〕26号` 废止 `2015〕34号`，但"谁是新版"仍要靠人读标题。
4. **`as_of` 还没接进检索**：现在 `stale` 用的是"今天"，问 2020 年的问题时应改用提问年份。

## 7. 面试讲法（30 秒）

> 我们一开始只抽文件自己的有效期，结果 9 道题判错——因为"被废止"写在别人的文件里。
> 后来加了一层关系抽取，143 条边，每条边带证据条款。
> 但**我们没拿它改排序**：降权、提权都试过，hit@3 各掉 5–8 个点，因为我们只有"谁废了谁"，没有"谁替代了谁"。
> 所以现在它只做标注：告诉我们"这条引用自 2020 年起已废止"，并多出一个指标——top-1 里还有 7 条引用了废止文件。

## 8. 时间点：同一个问题，年份不同答案不同

关系层刚做完时有个明显的坑：`status_at` 默认按**今天**判，于是问"2020 年建筑业工伤怎么赔"，
系统会说"2015 年那份已废止"——**用 2026 年的效力去否 2020 年的文件，结论是反的**。

### 做法

1. **从提问里取年份**：`validity.year_of()` 只认 19xx/20xx 且前后不接数字（避免把文号里的年份、金额、比例当年份）。
2. **带年份就把基准日改成那一年**：`as_of = f"{year}-12-31"`，报错页和 CLI 都会显示"判定基准日"。
3. **判"那一年有没有效"用区间相交，不用某一天的状态**：`in_force(doc, year)` —— 只要有效期区间与这一年有交集就算有效。
   因为 2020 年这类年份里，往往前 11 个月一份、12 月起另一份，**两份都算"那一年有效"**。
4. **带年份时不显示"已废止"，显示"该年内有效 / 该年无效"**：索引里冻结的"今天有效"不代表"那一年有效"。

### 实测

```text
问：2020年建筑业工伤保险怎么参加
判定基准日：2020-12-31

[1] ✓该年内有效  《沪人社规〔2020〕26号》九、/（二）（第 9 页 · PDF 原件）
[2] ✗该年无效    《沪人社规〔2025〕28号》正文（第 1 页 · PDF 原件）
[3] ✓该年内有效  《沪人社福发〔2015〕34号》一、（第 2 段 · 网页原文）
```

同一问题去掉年份，34 号会带 `⚠ 被《沪人社规〔2020〕26号》废止（2020-12-01 起）`；
问 2026 年，34 号直接掉出前三。

### 代价与边界

- 年份是**粗粒度**的：问"2020 年 3 月"仍然按整年算，月份会被忽略（`year_of` 只取年）。
- 无年份的历史题（"以前怎么规定的"）仍按今天判——这是已知误判源。
- 评测集里还没有时间类题目；`hit@1` 不变（55%），因为 dev 题都不带年份。要验证这条改动，需要按 AACL 论文的做法造**答案翻转题**（同一问题在两个日期答案相反）。

### 下一步（未做）

1. 造 10–20 条 answer-flipping 题：`2019 年 X 怎么算` vs `2026 年 X 怎么算`，两题答案必须指向不同文件。
2. 把 `as_of` 接进答案文本："按 2020-12-31 有效的版本判定"。
3. 月份粒度：`2020 年 3 月` 应该落到 `2020-03-31` 而不是年末。
